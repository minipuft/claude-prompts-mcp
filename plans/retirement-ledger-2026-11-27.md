# Retirement ledger

## Now (2026-11-27)

Goal: a spelling the product stopped supporting is refused with its replacement, is recorded once in a ledger that names when the refusal itself is deleted, and is named nowhere a user reads except one generated page.
Slice: T1 merged as #550. T2 is at its pull request from `feat/retired-spellings-refused`: every row done or killed, the ledger at 16 entries and 21 sites, the wording check live with five dated exemptions. T3 (rows 3.1 to 3.4) removes the four exemptions that name a form the product still accepts; it is cut from `main` after T2 merges.
Next decision: the owner's, neither blocking: whether `resource_manager`'s `include_legacy` parameter is renamed (a tool-surface change), and whether one config file name is retired (R34 and R68 accept both).
Constraint: the refusals are breaking and ride 6.0.0, which is unreleased (release PR #473 open, 5.1.1 latest). No upgrade command is added: owner ruling R33 (2026-09-15) stands.

## Intent

**Work type**: feature with breaking removals · **Confidence**: high on the ledger, medium on the `@` refusal (a sigil that also appears in ordinary text) · **Risk**: medium — five boundaries start refusing input they accept today.

Current state, measured on `main` at `c2d83a83` (2026-11-27): the product has three states for an old spelling: supported, refused, and a third one, "still works, with a note". The third state is what puts old spellings into the docs. Seven instances are live: the `<workspace>/<type>/` folder layout beside `<workspace>/resources/<type>/` (`server/src/runtime/paths.ts`), the `@` framework sigil (taught by all three examples in `server/README.md`), the script-tool fields `mode`, numeric `confidence` and `parameter_match`, the gate operator `=`, the flat skills-sync `exports` list, the `.mode` on/off config keys read by `cpm`, and the in-memory translation of a pre-5.0 config file (22 moved keys, 6 dropped), whose own header says "it is removed in 6.0.0" and which no plan row tracked. Refusals that already exist (`MCP_RESOURCES_PATH`, `prompts.directory`, the `analysis` section, the `sse` transport, a bare-string shell command on a gate) each carry a hand-written message and no removal date. The one docs gate for this class, `validate:profile-docs`, is keyed to one variable name. A finished migration guide is still published.

Desired state: two states only. A retired spelling has one ledger entry: what it was, what replaces it, the release that began refusing it and the date after which the refusal is forgotten. Every refusal site takes its replacement text from that entry. One gate reads the ledger and fails when an entry has no refusal, a refusal has no entry, a doc or shipped text names a retired spelling, a doc or message describes a spelling as still working, or an entry outlives its date across a major release. One generated page is the only place a user reads an old name.

## Design decisions

- **D1 — two states.** A spelling is accepted or refused. A warning that lets the old spelling through is not a state the product has. The gate fails on the wording of the third state in docs and in user-visible strings.
- **D2 — the ledger is data, the refusal is code, and the gate joins them.** An entry does not refuse anything by existing. A refusal site calls one function with the entry's id; the gate fails an entry with no site and a site with an unknown id. "Where do we hold this warning" is answered by a command, never by a hand-kept path list.
- **D3 — expiry is a date, enforced at a boundary.** Each entry carries `forgetAfter`. Before the date nothing happens. From the date the gate prints a warning on every run and annotates pull requests. A major release cut after the date fails until the entry and its refusal are deleted. A date alone never turns an unrelated pull request red.
- **D4 — default lifetime is six months** from the release that began refusing (planner default, owner may change: one sentence in `CONTRIBUTING.md`, dates are explicit per entry).
- **D5 — forgetting is a deletion.** When an entry is forgotten its refusal site, its test driver, its table data and its line on the generated page go in one commit. After that the old spelling is unknown input and gets whatever unknown input gets.
- **D6 — one page.** `docs/reference/upgrading.md` is generated from the ledger. Guides describe the current form only; they never carry an old-to-new table.
- **D7 — no upgrade command.** R33 ruled against one and scheduled the translation's removal for 6.0.0. An unversioned config file is refused with a message that names each old key the file carries and its replacement.

### Interfaces

`server/tooling/contracts/registries/retirements.json`:

```json
{
  "retirements": [
    {
      "id": "env-mcp-resources-path",
      "kind": "environment-variable",
      "retired": "MCP_RESOURCES_PATH",
      "replacement": "`MCP_WORKSPACE` set to a profile folder that holds `resources/`, or the folder listed in `paths.resources` of the profile's `config.jsonc`",
      "refusedIn": "6.0.0",
      "forgetAfter": "2027-06-01",
      "docPattern": "MCP_RESOURCES_PATH"
    }
  ]
}
```

- `id`: kebab, stable, the argument a refusal site passes. `kind`: one of `environment-variable`, `config-key`, `config-file`, `command-operator`, `resource-field`, `folder-layout`, `transport`, `tool-parameter`.
- `docPattern`: a regular expression no user-facing text may match outside the generated page. An entry whose spelling cannot be searched (`=`, a bare `mode`) carries a pattern narrow enough to mean it, or `docPattern: null` with `docPatternReason`.
- Runtime: `retirementNotice(id)` returns `{ retired, replacement, refusedIn }` text the site composes under its own prefix (`Refusing to start:`, a command refusal, a schema issue). The replacement sentence is written once, in the ledger.
- Gate `validate:retirements`, inside `validate:all`: (1) entry without a site, site without an entry; (2) entry without a driver in the table test that feeds the old spelling to the real boundary and reads the refusal; (3) user-facing text matching a `docPattern`; (4) expiry per D3; (5) generated page out of date; (6) third-state wording in user-facing docs and in string literals of `server/src`, `cli/src`, `hooks/` (row 2.7). Each check ships with a planted case that trips it.
- `npm run retirements:list` prints each entry with its sites and its date; that is the log.
