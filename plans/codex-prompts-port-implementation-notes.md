# codex-prompts port — implementation notes

Companion to `plans/codex-prompts-port-2026-08-03.md`. Conservative option taken, deviation logged, work continued.

## Deviations

1. **(Tier 2 / plan 2.3)** The plan's manifest row omitted the MCP server bundle. A codex-prompts plugin without `.mcp.json` ships hooks that reference a `prompt_engine` tool Codex doesn't have. Deferred to Tier 3: add `.mcp.json` after verifying Codex's env-interpolation rules for MCP server configs (gemini uses `${extensionPath}`; Codex equivalent unverified).
2. **(Tier 2 gate)** `codex plugin install <path>` does not exist in codex-cli 0.146 — installs are marketplace-mediated (`codex plugin add <name>@<marketplace>`). Gate satisfied via a scratch local marketplace (`codex-prompts-dev`, marketplace-relative `local` source path; an absolute path in the marketplace entry was NOT resolved). The dev marketplace + installed plugin were left in place for Tier 3 iteration; remove with `codex plugin remove codex-prompts` + `codex plugin marketplace remove codex-prompts-dev`.
3. **(Tier 2 finding)** Plugin cache copy drops symlinks: `hooks/lib -> ../node_modules/...` vanishes in `~/.codex/plugins/cache/<mp>/<plugin>/<ver>/` while `node_modules/` itself is copied. Tier 3 adapter contract updated: resolve lib via `Path(__file__).parent/"lib"` (dev checkout) with fallback `Path(__file__).parents[1]/"node_modules"/"claude-prompts"/"hooks"/"lib"` (cached install).
4. **(Tier 2 finding, safety)** A hook command that fails to launch (missing file → python3 exit 2) is interpreted by Codex as a BLOCK decision on that event — a half-shipped plugin can block every user prompt. Sequencing constraint: adapters must exist before any trust grant; README already instructs trust via `/hooks` only after install completes.
5. **(Tier 1, minor)** `npm-publish.yml` carried unrelated uncommitted changes from another session; this port added only the codex-prompts comment block + lock-refresh invocation lines. Commit staging must be selective.
6. **(Tier 0)** First `codex exec` invocation hung 3 minutes: `codex exec` announces "Reading additional input from stdin..." and blocks until piped stdin closes. All spawned invocations must close stdin (`< /dev/null` or write-then-close). Recorded in plan §Spike Results; relevant to `_build_codex_command` call sites.

7. **(Tier 3, upstream fix outside planned scope)** The live E2E surfaced `hooks/gate-enforce.py` crashing with TypeError on structured gate_verdict objects (the schema-preferred shape) — a pre-existing upstream defect masked by fail-open hook semantics on every client. Fixed in the same tier (defect fix with provably-correct target, per cleanup-standards no gate) + `hooks/tests/test_gate_enforce_verdict.py`. Also extended `SpawnConfig.client` with a `RALPH_SPAWN_CLIENT` env default so the codex adapter selects the spawn client without touching upstream ralph-stop code.
8. **(Tier 3)** npm treats same-version `file:` tarballs as cache-identical: after re-packing `claude-prompts-3.1.0.tgz`, `npm install` silently kept the old copy (lockfile integrity pin). Dev refresh requires `rm -rf node_modules package-lock.json && npm install`. Published releases don't hit this — version bumps change identity, and `synchronize-downstream-lock.js` polls for the exact new version.
9. **(Tier 3, open for Tier 4)** Plugin `.mcp.json` registers in `codex mcp list` (server `codex-prompts`, args showing un-expanded `${CLAUDE_PLUGIN_ROOT}`), but live serving is unverified — the E2E used the machine's global `[mcp_servers.claude_prompts_mcp]` (config.toml:74, pointing at the dev repo with `--client=codex`). Tier 4: verify interpolation by exercising the plugin-bundled server in isolation, then decide global-vs-plugin dedup (two servers advertising the same three tools is ambiguous for the model).

10. **(Tier 4 / 4.1)** Divergence path taken per the plan's own conditional. S1 re-probe: `SubagentStop` fires with the full Claude-compatible envelope (`agent_transcript_path`, `agent_type`, `stop_hook_active`, `last_assistant_message`; wait tool = `collaborationwait_agent`), but the delegated task prompt is unrecoverable in plaintext — encrypted in spawn `tool_input.message`, empty in the transcript's inter-agent `NEW_TASK` payload block, and the transcript is Codex rollout format (`response_item`/`event_msg` wrappers), not Claude message lines. Upstream extracts gate criteria from the Task prompt → unsatisfiable. Hook left unregistered; documented in codex-prompts README §Known divergences. Future option (not built — new design on an experimental surface): enforce via `pending_delegation` session state + `last_assistant_message` verdict scan.
11. **(Tier 4 / 4.2)** Catalog-free port instead of verbatim: Codex natively enumerates every `~/.codex/skills` entry in its `<skills_instructions>` injection (measured 16,460 chars on 0.146), so the upstream categorized catalog (~2,484 chars against the same dir) would be pure duplication. The adapter reuses upstream `scan_skills()` as an existence gate and injects only the protocol framing Codex lacks. Verified live: exact framing echoed back by the model, 107 skills counted.
12. **(Tier 4 / 4.4)** `codex-prompts` marketplace entry added with the declared GitHub url source — parseable now (`codex plugin list` shows it), installable only after the repo is pushed. Version drift 3.0.0→3.1.0 fixed. Also fixed README install commands that referenced the nonexistent `codex plugin install` subcommand (0.146 uses `codex plugin add`; local dev flow documented via a local marketplace).
13. **(Tier 4, carried Tier 3 finding c)** Plugin `.mcp.json` interpolation does not exist on codex-cli 0.146: an argv-logging shim substituted into the cached config received the literal string `${CLAUDE_PLUGIN_ROOT}` in argv AND env values, an empty `CLAUDE_PLUGIN_ROOT` environment, and the session directory as cwd. The manually-spawned cached server (paths pre-interpolated) boots cleanly, so the failure is purely host-side. Dedup decision: the global `codex mcp add` registration is the only working path on 0.146 and stays authoritative; the bundled `.mcp.json` remains as the forward contract; README documents the workaround.
14. **(Tier 4, environment repair)** The session scratchpad was wiped between Tiers 3 and 4, which broke `codex plugin list` entirely (the dev marketplace root lived there). Dev marketplace relocated to the durable `~/.codex/dev-marketplace`; plugin reinstalled from it; scratch `probe-hooks` plugin removed after the probes.
15. **(Tier 4, gate)** `npm run validate:all` fails at `validate:format` on files owned by ANOTHER session's uncommitted work (`README.md`, `plans/acquisition-recovery.md` style; three deleted-but-tracked plan files) — outside tier scope and left untouched per the shared-worktree provenance rule. Tier-owned files are Prettier-clean; every validate step downstream of the format check was run separately and is reported in the Tier 4 gate.

16. **(Post-Tier-5 isolation validation, user-requested)** Re-ran the E2E with the global `claude_prompts_mcp` server disabled per-invocation (`-c 'mcp_servers.claude_prompts_mcp.enabled=false'` — dotted overrides merge, so disabling beats table replacement). Result: the full loop (SessionStart skills framing → `>>` directive injection → `prompt_engine` via the plugin-derived server → Stop) passed with `--dangerously-bypass-approvals-and-sandbox` (`TOOL_NAME=mcp__codex_prompts__prompt_engine`, `RESULT_OK=yes`). Under the DEFAULT sandbox the tool call fails — see 17.
17. **(Two-layer root cause, measured via argv/stderr shims + direct JSON-RPC)** (a) **Codex 0.146 sandboxes MCP server children under a fixed profile**: they can write the session workdir and `/tmp` (proven — shim stderr log written to /tmp), cannot write `~/.codex` (cache/plugin-data), and `sandbox_workspace_write.writable_roots` additions show in the session banner but are NOT honored for MCP children. (b) **Upstream defect: the packaged claude-prompts server writes package-relative**, ignoring `MCP_WORKSPACE` — `node_modules/claude-prompts/runtime-state/state.db` + `logs/mcp-server.log` (config.json `logging.directory: "./logs"`); every `prompt_engine` call writes, so startup + tools/list succeed but calls die under the sandbox. Direct JSON-RPC against the same binary with a fresh workspace answers in seconds — failure is entirely write-path. Explains why daily usage works: sessions run inside the repo containing the server, so package-relative writes land in the session workdir. Upstream fix filed in the backlog (honor MCP_WORKSPACE in the packaged build); README + codex-plugins skill updated with the sandbox constraint.
18. **(Parity remediation Tiers 3-4)** Codex 0.146 does not interpolate `${CLAUDE_PLUGIN_ROOT}` and resolves a relative command from the session directory. The measured working launch is `command: node`, relative launcher argv, and `cwd: .`, which Codex resolves to the installed plugin root. Codex also strips project path environment from the MCP child, so the launcher and hook bootstrap use `<os.tmpdir()>/codex-prompts`; explicit `MCP_WORKSPACE` / `MCP_RUNTIME_ROOT` still win. The canonical `PathResolver` now separates package-owned resources from writable runtime state/logs.
19. **(Parity remediation Tier 5)** Server version 3.1.2 was selected because 3.1.1 was already published. Plugin version advanced to 0.1.2 after Tier 6 found the headless approval boundary. Final source/vendor/cache tarball and dist hashes match: tarball `f56402f9d37fb35742ca94474de18486a2ea5905960a6bcbfddb8a1d19819f9e`; dist `7c1b494598237591383e5fcc2b7b2c4da1d8522c971c00c050d5ad2850734368`. The old 3.1.0 vendor tarball was removed after acceptance.
20. **(Parity remediation Tier 6)** A normal `workspace-write` run initially exposed all three installed tool names but cancelled calls as `user cancelled MCP tool call`: headless `codex exec` had no interactive approval reader. Adding plugin MCP `default_tools_approval_mode: "approve"` was first verified in a reversible cache probe, then shipped in plugin 0.1.2. Final plugin-only run with global `claude_prompts_mcp` disabled completed `system_control` and `resource_manager`, reported exactly 26 prompts, and ended `DEFAULT_SANDBOX_PASS`.
21. **(Parity remediation acceptance)** Installed 0.1.2 protocol and three tool contracts match the global server exactly. Six non-catalog behavior cases normalize identically; prompt inventory intentionally differs 117 global → 26 public plugin prompts. All ten create/inspect/render/update/restart/delete mutation phases normalize identically. Runtime audit: DB/log outputs exist only under `/tmp/codex-prompts/server`; cache 0.1.2 contains zero `state.db*` or `mcp-server.log*` files.
22. **(Validation debt retained)** `validate:all` reaches `validate:format` and stops on unrelated shared-worktree state: formatting warnings in `CONTRIBUTING.md`, `README.md`, and `plans/acquisition-recovery.md`, plus four deleted tracked plan files. Package artifact verification separately exceeds current size budgets, and downstream npm install reports 24 moderate / 4 high audit findings. These remain release gates; parity-specific typecheck, ratchets, 159 suites / 1,917 tests, downstream 19 tests, protocol, behavior, mutation, and sandbox gates pass.
23. **(Post-restart cutover, 2026-08-04)** Fresh plugin-only validation passed after restart: system status, 26-prompt inventory, hook-mediated prompt execution, and supported `test_default count` rendering all succeeded under `workspace-write`. The first sentinel check used nonexistent argument `defaultValue`; rollout evidence showed the prompt correctly retained its default 42, and the corrected `count:"7"` check passed. Persisted `claude_prompts_mcp.enabled = false`; a subsequent session exposed only the three `mcp__codex_prompts__*` tools, reported 26 prompts, rendered count 9, and ended `GLOBAL_DISABLED_PLUGIN_PASS`. The orphaned 0.1.1 compatibility cache was removed; only 0.1.2 remains.
24. **(Resource lifecycle correction, 2026-08-04)** The full-catalog proof temporarily placed a `resources` symlink under `/tmp/codex-prompts`, which conflated persistent resource selection with disposable runtime state. Downstream 0.1.3 replaces that test fixture with a user-level `~/.config/codex-prompts/config.json` contract translated to the existing `MCP_RESOURCES_PATH`; explicit environment configuration wins, invalid paths fail startup, and no config selects the bundled 26-prompt catalog. Delete `/tmp/codex-prompts/resources` once installed 0.1.3 resolves the persistent config and passes protocol/inventory validation.
