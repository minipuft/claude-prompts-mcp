## Intent

Current: structured ordinary verdicts become strings at registration; live semantic criteria are refused. Desired: one typed verdict payload reaches an immutable, server-bound review; kernel results, tool results and bypasses retain their kinds in operational history.
Non-goals: evaluation archive/package, generic finding IDs, server model client, new database schema, artifact filesystem access, live installed catalogs/config, release or parent publication.

## Frozen interfaces and decisions

- Move renderer submission/entry/reminder input vocabulary below engine into canonical shared types. Preserve `string | GateVerdictSubmission` through ONE `gate_verdict`. `per_gate[index].evaluation` carries `SemanticEvaluationReport`; never encode it in rationale or a second request field.
- Public MCP Zod owns boundary validation. Lower engine contracts consume shared types and pure domain validation; engine must not import MCP schemas. No compatibility shim.
- Parsed verdict retains the original typed submission alongside display/legacy raw text. Authority resolves advertised indexes once into gate IDs; processor ordinary and detached paths pass the whole parsed verdict, never only `raw`.
- Review authority freezes resolved semantic criteria and definition digest at opening. Capture authority binds actual selected output bytes, target digest, reviewed node and a server-created attempt token before adjudication. Reports cannot provide expected pins.
- One step-output target is the live pilot. Default first flow captures output, receives server full binding/report envelope, then submits verdict. Same-call semantic reports may use server-computed actual user_response digest plus preissued gate/node/attempt/definition pins; report can never supply expected context. No captured target means no acceptance. Artifact syntax remains a standalone contract capability; live artifact criteria must refuse unavailable captured capability rather than reading arbitrary paths.
- Optional report.reviewer is {provenance: client_reported|unknown, provider?: nonempty, model?: nonempty, revision?: nonempty, context?: self|separate_pass|isolated_judge|unknown}; absent means unknown. Submitted host_verified is refused. Kernel validates shape but never uses identity for pass.
- `evaluation.mode: self | judge` remains routing. Semantic-only tier becomes `evaluation`; tool-only `check`; prose-only `reminder`; mixed stays `check` with explicit tool/model component kinds. Requested identity is separate from client-reported/unknown provenance.
- Tool coverage may auto-clear only complete tool-only requirements. Mixed gates require every required tool and semantic component. Kernel-derived failure/missing evidence defeats supplied PASS; advisory advancement retains actual failed observation and warning. Skip/override is a distinct recorded disposition.
- `GateVerdictSummary` retains evaluation observations, binding, provenance and disposition in existing `gate_verdicts_json`. Capture already carries whole summaries; mutate it only where a focused control proves a need. No DDL/bump.
- Opaque suite association is authored gate metadata only. Name `calibration_suite_id` accepted by parent; preserve opaque association. No case bytes/expected labels in runtime resource snapshots/rendering.
- Live GatePassCriteria union and public resource acceptance activate only in final tier after every enforcing reader/projection is implemented and tested.

## Existing systems audit and consequence tracing

Measured custody: prompt-engine schema entry/submission -> tools/index registration -> prompt executor -> shared execution request -> context getter -> request validator -> ParsedGateVerdict/authority -> processor answerReview -> summaries -> two capture shapes -> history/foldVerdicts.
Additional raw/string readers: temporary-gate-registrar FAIL join; authority.joinSentGates; response-capture stage `.length`; review-lifecycle.previousResponse. They are explicit rows, not presumed covered by widening a type.
Resource writes additionally pass gate-lifecycle-processor create/update/validate; parent T2 file list omitted it. YAML key registries and snapshot projection already preserve several fields by key-set contract; add explicit association only after canonical spelling is ruled.
Ground-truth coverage currently operates by gate ID, so a single passed tool can appear to cover a mixed gate. Semantic component exclusion is required before union activation.
The findings-plan premise that processor already has a refined Zod schema is absent here: processor parses through authority/free-text contract. Reuse one submission owner; do not invent generic finding scope. Semantic `criterion_id` does not become a generic finding ID.
Chains manager and execution-record store serialize whole review/summary objects. Inspect cold-load projections; source edits only for proven dropping readers. Current shared symlink dependencies and hooks stay untouched.

## Completion criteria

1. Registered STDIO and HTTP preserve typed ordinary and semantic submission through actual capture/history.
2. Server-issued pins survive cold load; changed catalog criteria cannot reinterpret pending review; replacement output/retry invalidates stale report.
3. Valid reports advance; failed, missing, malformed, stale, duplicate/unknown-ID and tool-failed mixed reports cannot clear blocking review. Advisory and bypass retain truthful dispositions.
4. Self/judge/runtime/export surfaces request the same public rubric/binding; requested identity never becomes observed provenance; gates-disabled/legacy ordinary flows retain behavior.
5. Resource create/update/inspect/history/compare/rollback and builder drafts preserve full definitions and only opaque suite association; private/sibling case material stays outside resource enumeration.
