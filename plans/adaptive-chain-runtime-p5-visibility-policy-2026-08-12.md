# P5 — Visibility Policy: Implementation Plan

**Master plan**: `adaptive-chain-runtime-2026-08-09.md` §P5 · consumes ledger finding **P4-F3**
**Produced by**: `chain-implementation_plan#4` (Discovery → Design → Verify-Paths → Plan-Table → Completion), 2026-08-12
**Sibling notes**: `adaptive-chain-runtime-p5-visibility-policy-2026-08-12-implementation-notes.md` (rulings, deviations, validation ledger)

## Intent

- **Work type**: feature · **secondary**: bug_fix (P4-F3)
- **Problem**: all server-sourced context flows to every step and every delegated envelope; step-targeted gates review every step → per-step declarative expose/withhold with the honest ceiling stated (server-sourced only), targeted gates review only their step, delegated steps provably excluded.
- **Risk**: medium-high — review-participation scoping touches the documented run-wide accumulator contract (gate-enhancement-service.ts:330); untargeted gates must keep inheritance.
- **External deps**: none.
- **Acceptance**: (a) a step declares withheld items a later step receives; (b) a `==>` delegated step provably does not receive them and its envelope carries a names-only manifest; (c) a gate targeted at node N reviews only node N; (d) docs state the server-window ceiling.

## Discovery (step 1, measured)

- **P4-F3 mechanics**: injection-side targeting filters at `gate-enhancement-service.ts:343` → private `filterGatesByStepTarget` (:530, node-id-first per OQ-P4-3, skipped-node veto, ordinal fallback). Review participation feeds from the UNFILTERED accumulator copy.
- **Accumulator writes ×2**: chain path :383-384; single-prompt path :247 (guarded by `isSinglePrompt`).
- **Accumulator readers ×4**: stage 13:219; **stage 14:183-198 (injection input — coupling constraint)**; response-assembler:684 (review display); internal-state:162 (decl). Stage 16 is NOT a reader (suspicion refuted by probe).
- **Injection axis today**: `INJECTION_TYPES = ['system-prompt','gate-guidance','style-guidance']` (injection.ts:400); per-step rules already exist (`StepInjectionConfig`, :302/:358). Visibility is a different axis: item routing between steps, not guidance timing.
- **Context chokepoints**: `previous_step_output`/chain-history templating at chain-operator-executor.ts:366-382; delegation `ExecutionEnvelope {chainHistory?, frameworkGuidance?, gateInstructions?}` at delegation/types.ts:24; delegation CTA :446-455.
- **Schema path**: `ChainStepSchema` prompt-schema.ts:75 → loader → `ParsedCommandSnapshot.steps` at chain-session.ts:61-64 (`Array<{inlineGateIds?, args?}>` — no nodeId [P4-F2], no visibility) → `ChainStepPrompt`.
- **Siblings**: `decisions/mutation/` (P4 pure-policy precedent to mirror); telemetry attribute-policy (infra redaction, different domain); GateSetResolver veto semantics.

## Design (step 2)

- **Objective**: per-step declarative expose/withhold over server-sourced data context + step-scoped review participation for targeted gates.
- **Non-goals**: client-window redaction (honest ceiling); replacing injection config for guidance types; node-id-addressed exposure (v2, needs P4-F2); numeric scoring; new SQLite tables.
- **Pre-flight**: 0 failures, compound none. Identification: pure decision over (step declarations, run step view, available items); shape = module of pure functions; placement `src/engine/execution/pipeline/decisions/visibility/` (matrix precedent: injection, mutation).
- **Decisions**:

| Decision       | Chosen                                                   | Rejected                             | Why                                                                                  |
| -------------- | -------------------------------------------------------- | ------------------------------------ | ------------------------------------------------------------------------------------ |
| Policy home    | `decisions/visibility/` pure module                      | inside InjectionDecisionService      | item routing ≠ guidance timing; overloads hierarchy resolver                         |
| Addressing     | item kinds v1                                            | node-id addressing                   | avoids P4-F2 dependency; OQ-P5-1                                                     |
| Review scoping | separate per-step review list                            | filter `accumulatedGateIds` in place | stage 14:183-198 reads it for injection; in-place filter couples review to injection |
| Delegation     | withheld items never enter envelope; names-only manifest | silent omission                      | honest boundary — subagent knows something was withheld                              |
| Schema         | `ChainStepSchema.visibility {withhold?, expose?}`        | prompt-level block                   | acceptance is per-step; prompt-level adds resolver depth without a driver            |

- **Interfaces**:
  - `ChainStepSchema += visibility?: { withhold?: VisibilityItem[], expose?: VisibilityItem[] }` where `VisibilityItem = 'previous_step_output' | 'chain_history' | 'unknowns_ledger'` (third item gated on OQ-P5-2)
  - `decideVisibility({step, priorDeclarations, runStepView}) → { withheld, exposed, manifest }`
  - `ExecutionEnvelope += withheldManifest?: readonly string[]`
  - `context.state.gates.reviewGateIds` (new, per-step) beside `accumulatedGateIds` (untouched)

3. `ParsedCommandSnapshot` lives at `shared/types/chain-session.ts:51` (not parsers/); steps shape needs the `visibility` field for blueprint round-trip.
