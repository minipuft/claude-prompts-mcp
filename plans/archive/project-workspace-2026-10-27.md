## Why

The server has one workspace per process (`MCP_WORKSPACE` / `--workspace`); the plugin install points it at the plugin data directory, shared by every project on the machine. Nothing reads the project directory for resources, although the state scope already derives from it (`shared/utils/project-scope.ts`: `CLAUDE_PROJECT_DIR`, then cwd). A project-specific resource has no home: `creed-fidelity`, a CloudySky design-bible gate, ships in the bundle and attached itself to unrelated chains until the activation fix on this branch (`ca7a1e59`). The harnesses already organise themselves this way — Claude Code `.claude/` and `.mcp.json`, Gemini CLI `.gemini/`, OpenCode `.opencode/`, Codex `AGENTS.md` — so a dotted directory at the project root with the product's name is the shape a reader expects.
