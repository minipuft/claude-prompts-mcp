# Skills Sync boundary — product surfaces describe translation only

## Now (2026-10-13)

Closed. Tier 1 is PR #485 (this repository); Tier 2 landed in the `~/.claude` repository as commits `dd89ca9` and `d494993`. Every row terminal; rulings R1–R6 and Q1 in §C and the implementation notes. Status `reference`: §A and §C carry the diagnosis and the owner's boundary rulings.

## A. Why (the sighting that cut this plan)

Commit `6f4b2309` (2026-08-23, "govern guidance and module boundaries") wrote the operator's fleet convention into two product docs: `docs/guides/skills-sync.md:10-45` and `README.md:286-300` state that `~/.claude` is canonical, that Codex and OpenCode are one-way projections, that downstream edits are never pulled back, and carry a "Project rule portability" table about the `AGENTS.md` projection. None of that governs what `skills-sync export` does. The same commit added the repo's `AGENTS.md` projection (`scripts/sync-project-guidance.js`, `guidance:sync`/`guidance:check`, pre-commit render, CI `validate:agent-guidance`), which is a legitimate repo-guidance contract documented in the wrong place.

One runtime leak: `resolveProjectRoot` (`server/src/modules/skills-sync/service.ts:961-983`) identifies the checkout root by the presence of `AGENTS.md`, a file that exists only because of the projection convention. It is the only runtime reader of `AGENTS.md` in `server/src`; every other reader is a repo validator.

Three `~/.claude` hooks maintain the convention and are hard-wired to this checkout: `hooks/skills/skills-drift.py` (SessionStart, runs `tsx scripts/skills-sync.ts diff --json` at a hard-coded path and forces `MCP_RESOURCES_PATH=~/.claude/resources`), `hooks/skills/validate-indexes.py` (catalogs exports by the `managed-by: claude-prompts-skills-sync` marker into `~/.claude/skills/_index.md`), and `scripts/sync-downstream-skills.sh` + `scripts/projection-health.py` (the Codex symlink layout the service's symlink refusal defends against).
