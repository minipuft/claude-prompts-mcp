# Skills Sync export fidelity

Scope: the **outbound** compile (`canonical YAML → SKILL.md`) that `npm run skills:export` runs.
Sibling plan `test-modernization-roadmap.md` owns suite-wide coverage shape (pyramid, %); this file
owns behavior-level gaps in one subsystem and does not restate its metrics.

**Each row is a suspected system defect, not a missing test.** The test is how the defect gets
confirmed or dismissed — that is why the "Falsifying mutation" column exists. Do not close a row by
writing a test that passes; close it by writing a test, mutating the named line, and watching that
test fail.

## Why this plan exists (method, and what it already proved)

On 2026-08-16 six defects were found by hand in export. Reintroducing each one as a source mutation
and re-running the suite showed **five of six were unobserved**, two of them by the entire
2571-test unit suite:

| Mutation                               | Old suite          | Now    |
| -------------------------------------- | ------------------ | ------ |
| Neuter `compileTemplate`               | 3 fail             | 3 fail |
| Drop chain-step `inlineGateIds`        | **50/50 pass**     | 1 fail |
| Manifest reports saved when it was not | **50/50 pass**     | 1 fail |
| Remove gate hook from frontmatter      | **50/50 pass**     | 1 fail |
| Deregistration reader returns nothing  | **2571/2571 pass** | 5 fail |
| Unconditional hook-enforcement claim   | **2571/2571 pass** | 1 fail |

Root cause of the blindness: all 42 pre-existing tests covered the **inbound** direction (`pull`,
`clone`) plus prune bookkeeping. `exportCommand`, both adapters, frontmatter emission, and the
gate/chain section builders had zero tests. The one mutation that was caught was caught sideways,
by `clone`'s reverse-compile assertions.

Closed by `tests/integration/skills-sync/export-command.test.ts` (12),
`tests/unit/skills-sync/deregistration.test.ts` (8), `tests/unit/skills-sync/gate-review-hook.test.ts` (3).
