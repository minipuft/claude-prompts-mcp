# Project Guidance Compatibility Projection

## Diagnosis

The repository has two instruction surfaces with different contents:

- `CLAUDE.md` plus `.claude/rules/*.md` are the tracked Claude-owned sources.
- `AGENTS.md` is locally ignored and contains stale, contradictory project guidance.

Codex and OpenCode prefer `AGENTS.md` when both names exist, so downstream clients currently miss
the canonical project handbook and scoped rules.

## Decisions

1. `CLAUDE.md` and `.claude/rules/*.md` remain the only authored project guidance.
2. `AGENTS.md` becomes a deterministic, tracked compatibility projection of those sources.
3. A pre-commit hook regenerates and stages the projection from the Git index.
4. CI byte-checks the projection on lightweight and full validation routes.
5. The old `AGENTS.md` content is not merged wholesale because it contains obsolete Node,
   transport, validation, and gate-precedence claims. Any still-valid unique constraint moves into
   a canonical Claude-owned source first.

## Removal condition

Delete the legacy hand-authored `AGENTS.md` content once every still-valid unique rule is represented
in `CLAUDE.md` or `.claude/rules/*.md` and the generated projection passes its drift check. The first
successful generation is that proof; no dual path remains afterward.

## Closeout

The legacy hand-authored projection is removed. `AGENTS.md` now contains only generated bytes from
the four canonical project sources, its negative drift probe fails as intended, and the simulated
pre-commit hook stages the same bytes it writes.

## Superseded shape

The initial full-body concatenation was replaced the same day by
`project-guidance-portability-2026-08-21.md`: Codex's documented default budget truncated it before
two rule bodies. The generator and ownership decision remain; the current projection uses selected
handbook sections plus conditional rule dispatch.
