# P4 — Adaptive Mutation v1

Phase 4 of `plans/adaptive-chain-runtime-2026-08-09.md`. Planned via in-thread `>>implementation_plan` (chain-implementation_plan#3, all phase guards green). Deviation log: `adaptive-chain-runtime-p4-adaptive-mutation-2026-08-11-implementation-notes.md`.

**Goal**: a deterministic policy layer under `engine/execution/pipeline/decisions/mutation/` that (1) inserts ONE investigation node after the current node when a blocking `unknown_discovered` lands, and (2) skips a declared-target downstream node when an `unknown_resolved` carries `resolution:'irrelevant'`. Both directions in ONE E2E test or the phase is not done. D2: model emits typed observations only; the server policy owns every mutation. D6: advisory by construction.

- Persistence: `run-registry.save()` (:139) rewrites `chain_run_nodes` per session (DELETE+INSERT by position, milestone column per row) — mutated node lists persist with the existing writer, no shape change.

- Cold-load (F10): manager.ts loadSessions():271-281 marks persisted sessions dormant; reconstruction from per-row tables must be proven under mutation, not assumed.

## Phase 2 — Design (pre-flight: 0 failures, compound none)

**Fire point**: stage 16, immediately after `applyObservations` — the only site holding the observation delta before any advance in the same call (F5: zero extra round-trips; an inserted node becomes the natural `nextAfter` CTA).
**Skip mechanism**: `milestone='skipped'`, row preserved; `advanceStep` loops past skipped nodes (traversal decision stays single-owner; `node-order.ts` stays pure positional).
**Target naming**: `unknown_discovered` gains optional `target_step_id` (F6's mutation-time semantics). Server never infers targets (D2).
**Insert identity**: fresh suffixed id via new `mintInsertionId` (never renumber).
**Cap accounting**: `chain_run_nodes.origin` column ('planned'|'inserted'), real writer, SCHEMA_VERSION 22→23 (ephemeral tables — bump-safe).
**Audit**: terminal-row counters `nodes_inserted`/`nodes_skipped` on `execution_records` (P2 v21 pattern, same two writers, reader = `execution_history`).

Interfaces:

```ts
type ChainMutation =
  | { kind: 'insert_investigation'; afterNodeId: string; unknownId: string; statement: string }
  | { kind: 'skip_node'; nodeId: string; unknownId: string }
  | { kind: 'none'; reason: 'no-trigger' | 'cap-reached' | 'target-passed' | 'target-absent' };
decideMutation({ delta, ledger, nodes, currentNodeId, insertedCount }): ChainMutation; // pure
ChainSessionStore.insertNodeAfter(sessionId, afterNodeId, { stepName, promptId, origin }): Promise<ChainNode>;
ChainSessionStore.markNodeSkipped(sessionId, nodeId, unknownId): Promise<void>;
```
