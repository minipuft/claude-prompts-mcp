## Why this exists

cell can hold: three of its claims are false, one whole section documents a capability that has no
implementation, and the direction the page should take is a decision, not a cleanup. Direction **B

`plans/tutorial-split-zero-install-2026-09-11.md`.

`docs/guides/gates.md` at 9.

## Standing constraints

- **Execution was blocked on the adoption rebaseline line (owner ruling, 2026-09-13), and the owner
  unblocked it on 2026-09-14** after taking that week's snapshot. The page still changes in one
  commit. It reaches readers only when the PR merges alongside the claude-prompts release PR, because
  a merge to `main` publishes a `docs/` page on GitHub at once.
- **There is no docs site.** Readers land on GitHub's blob view of a file: no sidebar, no nav, no
  "next". The only navigation is what is inside the file. Nothing in the rework may assume chrome.
- **The payoff needs a client.** `cpm` can `init` / `create` / `validate` / `list` / `inspect` a
  workspace with no server running, but has **no `run` or `render` command**, so no zero-install
  path can show a rendered prompt. That constraint is what rules D out of this plan.
- **"MCP Tooling Only" (CLAUDE.md §Core Principles) vs a tutorial that teaches YAML.** The
  resolution is a framing, not an exception: authoring through `resource_manager` is how a resource
  is MAINTAINED; the file layouts are how a reader UNDERSTANDS what was written and how an existing
  collection is imported. The page must say which it is doing at each point.

## Corrected premise — row 1.2's falsifier contradicts row 1.2's task

The task says "prerequisites + install link first". The falsifier says a reader "reaches _Run it_
without leaving the page". **An install link is leaving the page.** Both cannot hold.

Ruling: install goes **inline** (two commands, in the page), not behind a link. The falsifier is the
one that survives, because it is the one that describes the reader. Adoption row 1.2's falsifier
text is amended by Tier B's gate below rather than edited in two places.

## Direction (ruled 2026-09-11)

**B folded with A.** The page's job is the plan's goal metric — clone uniques, which is installs —
so its spine becomes install → ask Claude to write a prompt → run it → change it → read what was written. **Re-ruled 2026-09-14 by the owner**: the earlier spine opened by running a bundled prompt, but in an MCP client nothing runs on its own — the reader only asks in chat, and the model invokes the tools.
A's factual corrections ride in the same edit because they touch the same lines. Row 1.4's
single-exit change ships with it, so the two readings of the funnel (body vs exit) stay
distinguishable in the next window.

**Counter-vector, recorded so it is not re-argued:** 36 of 112 reaching this page is ~32%
clickthrough, which is strong, and the break may be AFTER the page rather than in it. Shipping 1.4
alongside 1.2 is what makes that testable — `docs/guides/gates.md` uniques is 1.4's falsifier and
arbitrates between the two readings without a second rewrite.
