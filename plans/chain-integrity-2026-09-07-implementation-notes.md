# Chain Integrity — Implementation Notes

Deviation log for `chain-integrity-2026-09-07.md`. Tier 0 receipts land here first, then move
into the plan's row status once a row closes.

## Tier 0 receipts

Receipts recorded in the plan rows 0.1–0.4 (2026-09-07). The one design consequence is ruling R7 in the plan: the write-path check runs before the write that scaffolds a chain's own one-level steps, so those ids are exempt and everything else must resolve.

| 1   | 2026-09-07 | 1.2 | `validateChainStepReferences` had THREE call sites, not the one the plan's Defect table names: `prompt-lifecycle-processor.ts` (update), `prompt-draft-service.ts` (create/validate) and `prompt-discovery-processor.ts` (`list detail:"full"` chain integrity block). | 3   | 2026-09-07 | 1.3 | The write refusal for `create`/`validate` is raised inside `PromptDraftService.prepare` (as an `errors` entry) rather than in the processor.                                                                                                                                                                     | `prepare` already owns every other create-time refusal and the processor already renders `❌ Prompt creation blocked — nothing written.` from it. Raising it in the processor would have been a second refusal path for one class of defect.                                                            |
| 4   | 2026-09-07 | 1.3 | `PreparedPromptDraft.warnings` / `PromptDraftResult.warnings` deleted; the `warnings` key stays in `structuredContent` as a literal `[]`.                                                                                                                                                                        | Chain integrity was the field's ONLY producer, so after the fix it is a reader with no writer. | 5   | 2026-09-07 | 2.1 | The load warning's structured fields are `{chainId, unresolvedSteps: [{stepIndex, promptId}]}`, not the flat `{chainId, stepIndex, promptId}` the dispatch named.                                                                                                                                                | R3 asks for ONE warning per broken chain. A chain with two dangling steps cannot carry two step indices in flat fields — the flat shape would either report one and hide the other, or force a second line and contradict R3.                                                                           |
| 6   | 2026-09-07 | 2.1 | The hook is `PromptRegistry.setLivePrompts`, not a new call in `data-loader.ts`.                                                                                                                                                                                                                                 | It is the single funnel BOTH load paths pass through after the merge: startup (`data-loader.ts:200`) and hot reload (`PromptManager.reloadPrompts` → `index.ts:218`). A `data-loader.ts` hook would have left the watcher reload unchecked — the same two-derivations shape this plan exists to remove. |
