## Proposed intended interaction and identifier contract

Owner accepted this source interaction contract on2026-10-13. Source acceptance and live transport/native proof are separate stages.

1. A prompt selector is one full registered reference: root, parent/child or deeper descendants. The category is separate and is not prepended. A selector is validated whole, never replaced by its first segment, basename or slash-to-dash slug. Lookup may retain existing typed spelling/name resolution, but returns the actual registered ID.
2. Canonical authoring remains existing lowercase snake segments. Accepted reference spelling preserves the current flat ASCII alphanumeric/underscore/hyphen language and extends it per safe slash-separated segment. Define that distinction in existing resource-ids.ts; do not duplicate it in parser families. Keep existing uppercase/kebab/digit-leading flat admission; no new length limit. The current bundled directory census has52 identities/15 qualified, all canonical; this is not personal-library census.
3. Validate the full directory-derived loaded ID, not only its YAML leaf, against accepted reference syntax before a run can be minted. Reject unsupported composed prefixes with a source path diagnostic; never silently rename existing catalog or persisted identities. Safe qualified legacy spellings remain exact references; spaces/dot/traversal/percent/backslash and empty segments are not admitted by this proposal.
4. A chain token is opaque workflow identity, not a filesystem path or URI. Existing chain-id-codec.ts owns chain prefix/run suffix and derives prompt-part validity from the defining reference owner. Formatter->validator->schema/internal validation->lookup must round trip every admitted producer ID. No normalization, case rewrite, encoding or aliases on chain_id. Existing #digits shape (#0/#01 included) remains; creation counters stillstart1. Acceptance is not proof the addressed run exists.
5. Explicit numbered tokens address exactly that run. Missing/stale explicit numbers must not silently fall back to a different bare/numbered run. Existing exact bare legacy rows are preserved; do not promise bare IDs mean latest because the actual store method is different. Pin this policy with real-store counterexamples before any lookup edit.
6. Literal, JSON-wrapped, chain/delegation and append readers consume the same full-selector reader. It validates the whole token and preserves raw quoted arguments. Invalid selectors fail before new run creation; missing valid selectors report the full requested name. Error generation must not fabricate an unknown root from a rejected qualified token. Reserved +/? operators remain reserved.
7. This fix does not silently introduce suffix modifier semantics. Current parser extracts one prefix modifier. Preserve/source-test prefix behavior and exact suffix bytes; assert modifier effects independently of selected prompt. A documented postfix promise, if found, is a separate contract repair. Use documented prefix position for clean behavior until that contract is measured.
8. Generator-owned hook patterns must derive from the same chain grammar, match complete IDs, and reject invalid-token prefixes. JSON/language fallback snapshots are projections, not new grammar authorities. Preserve request/server/tracked ID binding, refusal retention and truthful terminal clearing; structured IDs remain preferred where existing packets provide them.
9. Slash/# encoding belongs only to URI transport if its existing URI template needs it; raw stored/tool identities are untouched. URI control is separate from DSL selector/chain parameter grammar.
10. No schema migration or state wipe: existing slash IDs already occupy TEXT fields, exact slots and scope keys. Keep abort, pending/capture/report/attempt/node decisions, future conversation pause and object-only verdict delivery independent. Do not add review-based namespace aliases, new coordinators or fallback gates.
