## Why this exists

All three documented install paths ended with a command that failed for every installer except the
owner. Measured 2026-09-11 and re-measured 2026-09-13 against `origin/main` at `56138c35`:

| README line | Install path / section         | Command                                               | Bundled at `56138c35`  |
| ----------- | ------------------------------ | ----------------------------------------------------- | ---------------------- |
| 61          | Claude Code quick start        | `>>tech_evaluation_chain library:'zod' …`             | no                     |
| 99          | Codex                          | `>>tech_evaluation_chain …`                           | no                     |
| 135         | Claude Desktop                 | `>>research_chain topic:'…'`                          | no                     |
| 177         | What You Get, primitives table | `>>code_review target:'src/auth/'`                    | no, and exists nowhere |
| 205, 212    | Compose Workflows chain        | `>>review`, `--> security_scan`, `==> implementation` | none of the three      |
| 246         | Verification Loops             | `>>implement-feature`                                 | no, and exists nowhere |
| 328         | With Hooks table               | `>>analyze topic:'X'`                                 | no, and exists nowhere |

`tech_evaluation_chain`, `research_chain` and `review` existed only in the owner's personal store,
`~/.claude/resources/prompts` (92 prompts). The owner's shell exports `MCP_RESOURCES_PATH` at that store,
so every local check of the quick start passed for the owner and failed for everyone else. Root cause is
consolidation P1.6, which deleted 84 untracked prompts from the repo: it closed the git-visibility half of
that invisibility and left the documentation half with nothing enumerating it.

## Standing constraints

- **A fresh-install probe must strip `MCP_RESOURCES_PATH` and `MCP_WORKSPACE`.** This shell exports the
  first, and `npm run verify:mcp` inherits it (`spawnServer` spreads `process.env`), so on the owner's machine
  both serve the personal store over the bundle. That is the mechanism that hid this defect.
- **Relocation is a byte-identical copy, not a `resource_manager` write.** Recorded as a deviation from
  CLAUDE.md §Core Principles 1 in the implementation notes: the tool has no cross-root move, a `create`
  re-materialises files from fields, and the repo's precedent for moving resources between roots (P1.5, P1.6)
  is a copy proven byte-identical. The tool is the verifier instead — a clean-env server drives every
  command the README presents.
- **Chain-integrity refusal is not on `main`** (`fix/chain-integrity` is 7 commits ahead), so nothing refuses
  a chain with a dangling step at load or in CI. The clean-env drive is the only proof a bundled chain's
  closure is complete.
