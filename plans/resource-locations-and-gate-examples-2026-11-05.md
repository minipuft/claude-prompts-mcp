# Resource locations, hand edits and gate examples

## Now (2026-11-05)

Goal: a user sets where resources come from in one validated config key, the server reports what it resolved, a file edited by hand gets the same guarantees as a tool write, and a command-checked gate ships the examples that prove it.
Slice: none in flight. Tier T0 (three measurements) runs first.
Next decision: whether the plugin must stop pinning the workspace, settled by row 0.1.
Constraint: Tier T1 changes what an existing variable serves, so it ships in 6.0.0. Tiers T2 and T3 are additive and may land in 6.0.0 or the next minor. No new default directory is created under a user's home.

## Intent

**Work type**: feature with a breaking configuration change · **Risk**: medium — resource resolution decides what every prompt call can find.

Current state: five mechanisms across three channels decide where resources live (`MCP_WORKSPACE`, `MCP_RESOURCES_PATH`, `MCP_RUNTIME_ROOT`, the `prompts.directory` config key, a project's `.claude-prompts/` folder). Only `prompts.directory` is in the config schema, and it covers one of four resource types. Ten source files read `MCP_RESOURCES_PATH` from the environment directly. Setting it withholds the project folder at two sites in `server/src/runtime/paths.ts`. Neither `config get` nor status reports a resolved path or its source. A file changed on disk is detected, attributed as `filesystem` and reloaded, with no versioning call found in the hot-reload observer. `CLAUDE.md` forbids hand edits under `server/prompts/**`, a directory that does not exist. A skills export with `--client all` writes into, and registers, clients the operator left unregistered, and its preview omits the registration change. No gate definition carries an example of a passing or failing reply; 2 of 25 shipped gates run a command.

Desired state: one `paths.resources` list in the schema, ordered, later entries winning, with `"bundled"` as an explicit entry. A list without it serves only the listed locations plus the small set the server needs to run. The existing variables are overrides of the same keys through the ordinary default, file, environment, flag chain. A project folder always joins the stack. A disk edit records a version and a failed load is visible in the change log and status. Export touches registered clients only. A gate may ship examples beside its definition, and the server runs them for command-checked gates.

Non-goals: retiring `MCP_RESOURCES_PATH`, moving runtime state, executing examples for gates judged by the client model, changing how a workspace id is derived (owned by `plans/state-db-workspace-scope-2026-10-28.md`).

## Design decisions

| Decision                        | Chosen                                                                                                                        | Rejected                                                     | Why                                                                                                             |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------- |
| Path settings (R3)              | one `paths` block in the config schema; existing variables override its keys                                                  | retire `MCP_RESOURCES_PATH`; a startup warning only          | owner: consolidate, keep the capability, and make it manageable through the schema                              |
| Default locations (R3)          | none added; the resources and runtime split stays where it is                                                                 | a default under `~/.local`                                   | owner: do not write into a user's home                                                                          |
| Custom location semantics (R3c) | a custom location replaces shipped content; listing `"bundled"` keeps it                                                      | every layer always overlays                                  | owner ruling; someone who wants both lists both                                                                 |
| Run-required definitions (R3d)  | the set the server needs to start always loads from the package; everything else follows the list                             | a literal list that refuses startup on a missing definition  | a literal list would make nearly every user add `"bundled"` back                                                |
| Project folder                  | always joins the stack as the highest entry                                                                                   | an opt-out key                                               | it is what the feature promises; on 2026-11-05 the override left it inert on the owner's machine, by the source |
| Hand edits (R5)                 | a supported input: versioned, load failures surfaced; the handbook rule is deleted                                            | keep the rule with a corrected path; refuse disk edits       | the change tracker already treats the filesystem as a first-class source                                        |
| Skills export (R4)              | `--client all` means every registered client; export never creates a registration; preview reports registration changes       | every known client, with the change shown in preview         | a one-off export enrolled two clients the operator had left out                                                 |
| Gate tests (R6)                 | examples ship beside the gate as data; the server executes them for command-checked gates; test code stays in `server/tests/` | Jest files inside `resources/`; a consumer-pairing validator | owner: script-checked gates are the direction for validation; a workspace gate has no other way to be tested    |

### Interfaces

```jsonc
// config.jsonc, validated by config.schema.json
"paths": {
  "resources": ["bundled", "/abs/or/config-relative/library"]  // ordered; later wins; last non-bundled entry receives writes
}
```

```yaml
# resources/gates/<id>/gate.yaml
examples:
  - file: examples/pass.md
    expect: pass
  - file: examples/fail-missing-section.md
    expect: fail
```
