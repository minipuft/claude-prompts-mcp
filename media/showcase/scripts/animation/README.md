# Animation probes

Scripts that decide whether a timeline, a staging or a render of an animatic keeps the episode's rules. Each one reads contract files and, for the frame probes, a directory of `element-NNN.png` frames (`npx remotion render ... --sequence --image-format=png`). Run them from `media/showcase`.

Every probe prints a `control:` line first. The control is a synthetic fixture the probe must refuse (and a clean one it must accept); if it does not, the probe prints `refused:` and exits 2 without reporting, because a probe that cannot fail says nothing when it passes. Exit codes: 0 pass, 1 fail, 2 input error or control that did not trip. `--json out.json` writes the result. The fixtures come from `fixtures/make.py` (seeded, 320x180, at most 48 frames); `python3 scripts/animation/fixtures/make.py write /tmp/fix` writes them to disk for running a probe by hand.

## What the probes read

- `v3/timeline.json`: beats with `start`, `end`, `world`; crossing windows as `[start, end)` from the top-level `crossings` or a beat's `crossingIn`/`crossingOut`; `duration` or `durationInFrames`.
- `v3/xsheet.json` (`{rows: [...]}`), one row per frame: `frame`, `beat`, `world` (`home>crayon` inside a crossing), `key` (the key's name on the frame the animatic draws it from, which is its own frame only when it declares no hold before it: each key stays exactly its declared `hold`, then the next is drawn; else null), `hold` (the hold that key declares, else null), `breakdown` (the favour of a breakdown on the frame it starts, else null), `camera {x, y, zoom, rot|rotation}` (three decimals), `emitter {x, y, hex}` (stage pixels; null on a frame with no light), `phase` (`hold`, `move`, or inside a crossing its thirds `reduce`, `line`, `refill`). Written by `npm run xsheet` from `src/scenes/animaticPlan.ts` together with `v3/xsheet.html`. Without `--xsheet`, `xsheet.json` beside the timeline is used when it exists.
- Camera model: `x, y` is the stage point (1280x720) at the centre of the view, `zoom` scales about it, `rot` turns the scene clockwise; identity is `640, 360, 1, 0`. This is `cameraTransform` in `src/library/animation/camera.ts`; the frame probes invert it to cut the figure out of a moving frame. Render probe frames with `--props='{"captions":false}'` (the Animatic's caption strip is review chrome that covers the figure's boots).
- `v3/light.json`, for `probe-colour.py --contract`, written by `npm run light` (`compile-light.mjs`: shots.json hue pairs, the ledger's effects, `worlds/*.json` radiance, each beat's blocking emitter) and read by the Animatic when it covers every beat and crossing. `start` and `end` are fractions of the frame; `on` and `off` are absolute frames (`off` exclusive):

```json
{
  "beats": {
    "arrival": {
      "pair": {"radiance": "#0a51fb", "accent": "#fad204"},
      "emitter": {"anchor": "box seam", "start": [0.4, 0.8], "end": [0.6, 0.5], "intensity": 0.8, "colour": "#0a51fb", "on": 0, "off": 178},
      "radiance": "settled", "grain": "low"
    }
  },
  "crossings": [{"from": "the-frame", "to": "art-world", "frames": [775, 845], "path": ["#17263a", "#a030e0", "#e1750c"]}]
}
```

`beats` may also be a list with an `id` on each entry. `emitter` may be a list for a beat with a handoff inside it, and is absent for a beat with no light; `on` and `off` are absolute frames and default to the beat's own range.

- `v3/roles.json`, for `probe-eyetrace.py` and `probe-colour.py`, written by `npm run roles` (`compile-roles.mjs`, from `src/library/tokens.ts` and `v3/worlds/*.json`): the fixed fills the frame probes mask (identity pigments, the human's, kit's and gadget's roles, each world's field and texture colours, and `plates`: the human's cutout, whose palette the probes sample at run time). Absent, the probes mask only the two identity pigments and say so.
- The emitter in `v3/light.json` has a luma floor: `compile-light.mjs --floor <luma>` (default 200) lifts an emitter colour at its own hue until colour x intensity draws at least that luma, and raises an intensity too low for white to reach it (the ledger's "tiny" 0.5 becomes 0.8), because the light is the brightest thing outside the fixed fills (C6, D44, C29). A crossing path walks between the lifted colours.

## Layers, shots and slices

**Props.** The animatic draws every actor a beat's blocking names (`blocking.actors`: `box`, `bubble`, `gadget`, `stalk`, `structure`) as the project's hand-coded props in flat settled role fills (`src/library/worlds/actors.tsx`; the home world's `actors` part, `partsOf('home')`). They are placeholders, not the film's art: none of the muse sheets is accepted. The blocking's `x, y` is an anchor whose meaning `actors.tsx` fixes per prop (the box and stalk stand on it, the structure's base is on it, the bubble is centred on it, the gadget hangs from its dial), `scale` multiplies the prop's native size, and a stalk with `facing: left` is mirrored. An actor name with no drawing is an error. `omit: ["box"]` on `Animatic65` (`--props='{"captions":false,"omit":["box"]}'`) leaves the named actors out: `node scripts/animation/render-props.mjs <dir>` renders the stills (per beat that names actors, the frame in the middle of the beat, and once per actor without it) and **probe-props.py `<dir> v3/blocking`** (gate `animation-props-drawn`) requires each actor's picture to differ from the one without it by at least 600 pixels at 1280x720 (area-scaled) with the centre of the difference within 420 stage pixels of the anchor; an actor with no stills pair is a failure. Control: a blob on the anchor passes, a pair with no difference (the actor omitted from both) is refused, a difference in the far corner is refused. The figure's pose track reads the shot's key sheet where one exists (`animaticPlan.ts`: s01 through `poseChartFrom`, which refuses a pose sheet whose keys are not the key sheet's; s02 its key sheet), holds only, and the placeholder `liftChart` elsewhere.

**`Animatic65Figure`** (`layers="figure"` on `Animatic`, as `ShotS01Figure` is for s01) draws only the human, flat and filled, at the beat's blocking under the camera, on the field colour, in every frame including a crossing's. Render it like the animatic (`npx remotion render src/index.ts Animatic65Figure out/animatic-fig-seq --sequence --image-format=png --scale=0.5`) and hand it to `probe-twos`, `probe-holds` and `probe-loop` as `--figure-frames`: a crossing needs no exemption for the figure there, because only the world's fills morph in a crossing and they are not in that layer. The figure's placement (scale, x, y) steps at a cut with its pose and does not ease like a prop (`animaticPlan.ts`), so the layer changes only where the exposure sheet has a key.

**`Animatic65FigureLine`** (`layers="figure-line"`) is the same with the figure as the line world draws it (contour only, `reducedLine` of the line contract at full reduction, no arch, gates, floor or props). `probe-loop.py --figure-line-frames` reads closure and clipping there: in the full frame the floor grid runs through the figure's legs into the crop's border and merges with its outline, which reads a closed figure open. Render only the line-phase frames (`--frames=` the xsheet rows with `phase` or `world` `line`).

**The emitter in the xsheet** carries `strength`: the share of its intensity the picture draws (1, except inside a crossing, where the world's light fades out while it reduces to line, is off in the line world and fades in as the next world refills, `emitterStrength` in `xsheet.ts`). `probe-eyetrace.py` measures only frames where it is 1 (`--min-strength`). The glow's radius is 260 stage px in the animatic and `glowMask` follows it (a 200 x 160 box at the 170 the contracts name): at 170 the glow, with the props drawn over half of it, was smaller than the 0.5 % the eye trace ranks and its centroid wandered (65 % off at the start of the shaded beat).

**`--shot <id>`** on every probe measures one shot's slice of the timeline: the beats of the shot (its `beat` list in `v3/shots.json`, plus every `v3/blocking/<beat>.json` whose `shot` names it), their frames, and the crossing windows that touch them (a window the slice ends inside is kept and read on the side it has). Frame numbers stay film frames.

## Contract probes (no frames)

**probe-timeline.py `v3/timeline.json`** checks that the beats run from frame 0 with no gap or overlap and sum to the duration, that each crossing window starts inside the beat it leaves and ends inside the beat it enters, that every world is one of `home`, `crayon`, `line`, `shaded` (`--worlds` to change), and that each beat has at least 11 frames clear of crossing windows unless it carries `intentionalHold: true`. Control: a planted 0-frame beat, a 3-frame gap, a crossing outside its beats, an unknown world and an 8-frame beat are each refused.

**probe-blocking.py `v3/timeline.json v3/blocking`** checks one `blocking/<beat-id>.json` per beat: every actor the ledger's `actions` name for that beat has `x`, `y` and a scale (`--ledger`, else `beats-v2.json` beside the timeline; `world` is exempt, `--exempt` to change), `emitter.start` and `emitter.end` are inside the frame (values up to 2 are fractions, larger are stage pixels), `card` is set, and the Codex, Clawd and human-crop boxes do not overlap. It reads both the `actors` map the prompt describes and the top-level `figure`/`codex`/`clawd`/`frame` of the checked-in files. In the checked-in files `emitter.start` and `emitter.end` are `[x, y]` stage pixels and `card` is an id on `v3/references/board.json`. Control: an actor with no position, an emitter outside the frame, no card, overlapping boxes and a beat with no file are each refused.

**probe-colour.py `--contract v3/light.json --timeline v3/timeline.json`** (rubric C30) checks that each beat carries exactly one hue pair (and the shot's D74 pair when `shots.json` covers it), that emitters never overlap and hand off 2-4 frames apart (unless a beat with no emitter sits between), and that each crossing's `path` runs on the shortest arc from the from-beat's pair to the to-beat's without turning back or going grey. Control: two emitters live on one frame, a 1-frame handoff and a hue path through green are each refused. It also holds each crossing path's value and chroma (C15): no interior sample more than `VALUE_MARGIN` (0.05, the same constant as `PATH_VALUE_MARGIN` in `light.ts`) under the lower endpoint's value (largest channel), nor under the lower endpoint's chroma (largest channel minus smallest, one 8-bit level of rounding); `compileLight` raises a blended sample to those floors (`hslPath`) and `parseLightContract` refuses a hand-edited path that dips. Its control adds a path through a tan (refused on value) and through a grey (refused on chroma) beside a hue walk between the same ends that holds both (passes).

**probe-poses.py `v3/poses v3/keys v3/charts [--shot <id>] [--joints keys|solved]`** (rubric C21, C16) checks the pose pass of every chart that has a rig actor, which must have `v3/poses/<shot>.json` (`src/library/animation/pose.ts`: per key the line of action as class `C`/`S`/`I`, `bow`, `sign`; the weight foot and `over`; the lead arm and leg; `twinned.why`; per consecutive pair the breakdowns with their arc; secondaries with `lagDrawings` 1-3 (drawings on twos, 2 frames each: a shot drawn on fours lags one of its drawings with 2) an optional `side` (`L` or `R`, the arm the part is) and `stretch` 0-1, default 0 (0 rides the parent and lags only in angle, a limb; 1 stays where it was in the world and the bone stretches to reach it, cloth; `parsePoseSheet` refuses a value outside 0-1); moving holds) and `v3/keys/<shot>.json`. Each failing item is a line naming the key or breakdown; a category with nothing wrong is one ok line. `--joints keys` (the default) measures the key sheet's joints, not the pose sheet's claims; `--joints solved` measures the line of action, twinning and weight of each pose key's `solved` joints instead (what `solvePose` draws for the declared spec, written by `npm run solve-poses -- <shot>`), so a pose sheet can be judged before any plate exists; a sheet with a key that has no `solved` is refused (exit 2, naming the command), and the other categories read the same files in both modes. The gate `animation-pose-contract` runs `--joints solved`. Control for the mode: solved joints of a straight spine declared S are refused on line of action only, the clean sheet with straight solved joints fails under `solved` and passes under `keys`, a sheet with no solved joints is refused, and solved joints equal to the key sheet's pass every check. With `keys`:
- *keys*: every chart key has a pose entry on the same frame and the key sheet has it there; every pose key has a `moment`.
- *line of action*: the spine fit (`spine_curve` in `probe_common.py`, the formula of `spineCurve` in `pose.ts`: a cubic whose control points sit at chord thirds, fitted by ridge least squares to the shoulder midpoint, torso and neck against the root-to-head chord, in fractions of `heightPx`) reads as the declared class and on the declared side, and its bow is at least 0.06 unless the key declares class `I` and its `moment` says why (because, so that, deliberate, stiff, rigid, frozen, locked). Class `I` is a bow under 0.04; `S` needs both lobes at 0.03. The lower lobe of an S is extrapolated: torso, neck and head bunch within 13 percent of the spine, so the S term is ridge-regularised. `sign` is the side: +1 when the spine bows toward the left-hand normal of the root-to-head chord (for an S, the side of its first lobe from the root), -1 on the other. A measured sign opposite the declared one is its own line, `<key>/sign` ("the spine bows to side +1 ... and the key declares side -1: a bow on the wrong side of the chord"); a key that declares or reads class `I` has no side to judge.
- *twinning*: score at most 0.7 (`twinning_score`: the smaller of the mirrored and the parallel angle between left and right bone, over upper arm, forearm, thigh and shin, as 1 - mean/40 degrees) unless `twinned.why` is present.
- *weight*: a foot is declared and the root's x is between the ankles, within 25 percent of the stance width of where `over` puts it (the midpoint for `both`).
- *breakdowns*: every consecutive key pair has a breakdown with `arc.offsetPx` not 0 or an authored `joints` pose; a pair where no joint travels 0.08 of the height is a short straight move, allowed and said so.
- *lead arm*, one line per move with a lead arm: the shoulder, elbow and wrist of the to-key's `lead.arm` belong to no secondary that lags on that move, because the arc probe judges the lead wrist as authored motion and a lag would put its mechanics into the path. A secondary names the `side` it is and then does not lag on the moves that side leads (`poseChartFrom` skips its lag from the hold's end to the key's frame plus the lag, and the overlap and arc checks read it as body there); a secondary that holds those joints without that side is refused, by `parsePoseSheet` too.
- *timing shape* (C28), one line per move, from the end of a key's hold to the next key. The drawings of a move are the breakdowns the chart plays there: the authored ones, else the two automatic thirds `marksIn` adds, counted as `listBreakdowns` lists them. A move has 3-6 drawings; at most one `anticipation`, one `overshoot` and one `settle`; any number of `passing`. The stored `favour` is always positive and a drawing sits at a position along the chord (first key 0, second key 1): `passing` and `settle` at `favour`, `anticipation` at -0.25 x `favour` (a drawing BEFORE the from-key), `overshoot` at 1 + 0.25 x `favour` (past the to-key). Bands: anticipation -0.15 to -0.05 (favour 0.2-0.6), passing 0.25-0.75 and rising, overshoot 1.05-1.15 (favour 0.2-0.6), settle 0.9 or more. By frame, anticipation < passing < overshoot < settle; no drawing inside the hold, none on a frame another drawing has, none with the favour of the drawing before it (the exposure sheet marks a breakdown only where the favour changes, so it would not show). `parsePoseSheet` refuses the same things. One drawing is held at most 4 frames (the hold probe reads a longer run as a hold), so a move of n drawings from a hold of h frames is n x 4 frames or fewer after the hold: the key frames and holds decide whether 3 or 6 fit.
- *secondaries*, *holds*: lagDrawings 1-3 over joints the key sheet has; a key whose hold is over 11 frames has a `movingHold` or a `face`.

Control: a straight spine declared `S`, a spine mirrored to the other side of its chord and still declared the original sign (named `A/sign`; the same mirrored spine declared the other sign is accepted), mirrored limbs with no `twinned.why`, a long move whose only breakdown is a favour, a move of ten drawings, a passing drawing at 0.10 and a lead-arm joint declared as a secondary with no side are each refused (on their own check and no other), and a clean synthetic sheet (a move of anticipation, passing, overshoot, settle: four drawings, the lead hand naming its side) is accepted on every check.

## Frame probes

**probe-twos.py `<frames> --timeline ... [--figure-frames <dir>] [--shot <id>]`** (C27) measures that the figure's drawing changes only on even frames while the camera may move on every frame: it inverts the xsheet camera, cuts the figure crop (`--crop x,y,w,h` to override; the default is the stage figure crop scaled by the frame width, 380,0,500,720 at 1280) and lists every odd frame on which it changed. On full frames crossing windows are exempt (the world's fills change on every frame there and a pixel change is not a drawing); with `--figure-frames` (the figure-only render, below) the figure is read from that layer and NO window is exempt. Where the camera moved between two frames the crops are compared through a box blur of 10 stage pixels at a summed-RGB threshold of 96 (otherwise exact, threshold 24): sub-pixel camera moves resample every 1 px ink edge, which read as 2500-8000 changed pixels per frame on the animatic and as 0 blurred, while a real key change stayed at 6600-20500. The xsheet carries the camera to three decimals (`x`, `y`, `zoom`, `rot`): at one decimal a camera easing out of a move at 0.1 px per frame read as unmoved and the exact comparison saw the sub-pixel move as a drawing. Control: a sequence with a change on frame 7 fails; the same with changes on even frames only and a camera panning every frame passes; an odd-frame change inside a crossing window fails on the figure layer and passes (exempt) on full frames.

**probe-holds.py `<frames> --timeline ... [--figure-frames <dir>] [--shot <id>] [--no-pops]`** (C28) measures how long each drawing is held: a drawing held more than 4 frames is a hold and must last 11-27 frames, unless a key row in the xsheet declares a hold of 28 or more (listed in the output). The drawings between two holds are the move and must number 3-6. Two holds with nothing between them are counted as pops, which a holds-only animatic is made of; `--no-pops` fails them. The animatic draws each key for exactly the hold it declares and then the next key (`heldDrawing` in `keys.ts`; a key that declares none stays until the next key's own frame), and the xsheet marks a key on the frame it comes on, so `rest` with `hold: 24` is 24 frames on screen, not the 36 until the key after it. When the xsheet has key or breakdown rows, a pixel change with no such row within 1 frame is boil on full frames (the board allows it inside a hold, and the crayon world redraws the figure about six times a second): it is counted and does not end a hold. Without key rows every change counts. On full frames crossing windows are exempt. With `--figure-frames` no window is exempt and nothing in the layer boils, so a change with no key or breakdown row within 1 frame is a failure of its own (`pose changes on the sheet`, naming the frames). Control: a 40-frame hold fails, a 16-frame hold with a 4-drawing move passes, a declared 40-frame key hold passes and is listed, a 1-drawing move fails, a pose change planted inside a crossing window with no key row fails on the figure layer and is exempt on full frames, the same change with a key row passes.

**probe-screentime.py `[<frames>] --timeline ... --xsheet ... [--shot <id>]`** (C26) measures that each beat is on screen for the frames the timeline gives it: the xsheet's first and last frame for the beat within 1 frame of the timeline, the rows contiguous, the world right outside crossings, and every crossing window inside both beats (a window a shot's slice ends inside is checked against the beat it has). Control: the same xsheet against a timeline with one beat shifted 3 frames fails.

**probe-eyetrace.py `<frames> --timeline ... --xsheet ... [--shot <id>] [--blur 8] [--roles v3/roles.json]`** (C29) measures that the brightest region outside the fixed fills centres within 3 % of the frame width of the xsheet emitter. The fixed fills (`v3/roles.json`, `npm run roles`, each with a 28-RGB neighbourhood) are the identity pigments, the human's, kit's and gadget's role colours, the palette of the human's cutout (its pale contour and shading are not its five roles: a frame reads the contour (222, 198, 198), no role within 28) and each world's own texture colours (the crayon paper and stroke palette, the shaded world's edge colour): they are fixed per palette, not light (C1, C2, C6), and what outranks the light must be outside them. Per frame the luminance of what is left (masked pixels count as black) is box-blurred over 8 stage pixels, the brightest 0.5 % of the blurred map is taken (ties kept) and its centroid is measured against the emitter: a region, not a pixel, because the anti-aliased edge where a fill meets its neighbour is a bright speck a light is not. **One emitter space: stage pixels** (1280x720, as the xsheet carries them), projected through the row's camera onto the frame and scaled to its width; there is no screen-space option (the old `--emitter-space` default `screen` read the same point as frame coordinates and was wrong wherever the camera moved). Frames whose row has no emitter are skipped and counted; a run that skips every frame fails. Control: a blob 10 % of the width off the emitter fails, the blob on the emitter passes, identity, garment and kit-contour patches brighter than the blob are ignored (read unmasked they would put the offset at 46 %), the same blob against an emitter projected through a camera that moved 140 stage px fails, 120 lone white specks brighter than the blob do not move the blurred offset (2.2 %) and do move the unblurred one (8.7 %).

**probe-loop.py `<frames> --timeline ... [--figure-frames <dir>] [--shot <id>]`** measures that the figure's outline is one closed loop on every frame of a line phase (xsheet `phase` or `world` equal to `line`), by the method of `measure-worlds.py loop`. Clipping is its own line: a figure the frame cuts off cannot be a closed loop whatever the world draws, so with `--figure-frames` every line-phase frame is read on the figure layer for ink on the frame's own edges and `figure inside the frame` names the frames and the edges (top, bottom, left, right); without it the line is not measured and the probe says so. Control: a closed outline reads closed and the same with a 4 px band erased across the shins reads open, on a synthetic figure and again on the first real line-phase frame; a figure that fits reads inside the frame and the same figure 30 rows lower reads clipped at the bottom.

**probe-colour.py `<frames> --timeline ... [--contract v3/light.json] [--shot <id>] [--roles v3/roles.json]`** (C30, C24) measures that the saturated pixels outside the fixed fills (the set the eye trace masks, above: the identity pigments, the human's, kit's and gadget's role colours, the cutout's palette and the worlds' texture colours) of each frame sit inside the beat's hue pair plus or minus 15 degrees (at most 2 % outside), and that across a crossing window the dominant hue moves from the from-beat's pair to the to-beat's without a detour. What is left to grade per beat is the radiance layer, which is what C24 and C30 govern. Pairs come from `light.json` or `shots.json`. Control: a frame with an off-pair saturated patch fails, a crossing that swings through green fails, a clean sequence with identity, garment and kit-accent patches (saturated, off both pairs) passes. The same floors are read on frames, per crossing window: the dominant colour of each frame (the most common 16-level colour, `dominant_colour`) must stay above the lower of the window's first and last frames' value less `VALUE_MARGIN`, and above their lower chroma less `CHROMA_SLACK` (4 levels: the rasteriser's 2 levels on each of the two channels a chroma subtracts). A straight blend never leaves the range between its ends in value, so this refuses a path pulled below both ends and does not refuse a plain fade from a light field to a dark one, however muddy its middle reads (animatic 02: value 0.92, 0.30, 0.05 at 1135, 1150, 1160 passes; the study's C15 grade names that fade, which no floor set by the endpoints can see). A window with under 3 readable frames is listed as unmeasured.

**probe-determinism.py `<frames-a> <frames-b> [--subset] [--shot <id>] [--levels 2] [--share 0.0001] [--bytes]`** (C12) measures that two renders of the same frames match within the rasteriser's own noise: a frame matches when no more than 0.01 % of its pixels (23 at 640x360, 92 at 1280x720, rounded down) differ by more than 2 levels in any channel. The same anti-aliased line is quantised to a coverage step by Chromium's SVG rasteriser and lands one step either way from run to run (measured on the animatic: up to 1400 pixels one level apart on line and shaded frames, and at most 30 pixels one 53-level coverage step apart); a different picture is far over the bar (the crayon noise bitmap drawn from the live SVG on a tab's first frame was 45 000 pixels, up to 43 levels). `--bytes` is the strict form (sha256 of each file). Control, on a 320x180 fixture frame (allowance 5 pixels): two writes of one frame pass; 1 pixel 1 level off passes; 40 pixels 1 level off passes; 60 pixels 40 levels off fails; every pixel 3 levels off fails. **A single pixel 40 levels off is inside the allowance by arithmetic (1 of 57 600 is 0.0017 %), so it is tolerated and reported as such; `--share 0` refuses it.** Row 5.4 asked for a planted single pixel to be refused under this tolerance; the two cannot both hold, and the tolerance won.

**probe-inbetweens.py `<figure-frames> --joints out/<shot>-joints.json --poses v3/poses/<shot>.json [--xsheet ...]`** measures the drawings between holds on the figure-only render (`npx remotion render src/index.ts ShotS01Figure out/<shot>-figure-seq --sequence --image-format=png`) and the joints the renderer drew (`npm run joints -- <shot-id>`, below). A move runs from the end of one key's hold to the next key's frame; the path of a joint is the pose before the move and one position per drawing. Per move (H is the pose sheet's `heightPx`):
- *arcs*: the lead wrist (the destination key's lead arm), the head and the root each run an arc on a move whose chord is at least 0.08 H: over the pose before the move and one position per drawing, (a) the signed perpendicular deviation from the chord has one sign on every interior drawing (under 1 px is zero: a bow to one side, not a zigzag), (b) the projection onto the chord never goes back by more than max(1 px, 0.005 H) (4.4 px at 880) from one drawing to the next, except INTO a declared anticipation and OUT OF a declared overshoot (the kind of each drawing is the pose sheet's: the kind of the last breakdown on or before the frame the joint is showing, which for a part that trails is 2 x `lagDrawings` frames earlier), (c) the turn between consecutive segments never exceeds 90 degrees (segments under the same bar are skipped) except at the vertex of those declared reversals, and (d) the largest deviation is at least max(4 px, 0.02 H). Any other step back fails (b). A failing path names the letters, the joint and the frames. A part that trails (a secondary's joint) is followed on past the key's frame to the first drawing within the bar of where it settles, because the drawing the key's frame shows is still the lagged one and the chord ends where the part does.
- *spacing*: on a move of 4 or more drawings the lead wrist's per-drawing distances ease (first and last each smaller than the largest in the middle); all within 15 percent is "even spacing".
- *overlap*: each declared secondary's joints come within 10 percent of their travel of the end pose at least 2 x `lagDrawings` frames (the delay `poseChartFrom` gives it, whatever length the move's own drawings have) after the joints that belong to no secondary; drawings are followed 8 frames into the next hold. A secondary landing inside the hold's first drawings is this check's, not the moving hold's, and a move's last breakdown may be an overshoot: nothing requires it to settle short of the key.
- *moving holds*: over a declared moving hold the ink centroid of the figure crop (camera inverted with the joints rows' `camera`, or `--xsheet`) drifts by a net 0.5 stage px or more, with no 2-frame step over `driftPx` x stage-px-per-key-px + 0.5. The hold is measured from the key's frame plus twice the largest `lagDrawings` of any secondary (until then the last secondary is still landing, which is overlap, not a hold) to the first drawing of the move that leaves the key, or to the end of the drift (`over` frames) when that comes first (`firstDrawingAfter` in `pose.ts`: its first breakdown, else the next key; `poseChartFrom` keeps the drift until that drawing, so the figure does not snap back on a drawing of its own; once the drift has run there is nothing left to measure, and a camera that zooms through the hold only adds inversion noise). Net shift, so redrawn contours that sum to nothing do not pass for a drift. Stage px per key px: `--stage-per-key`, else the layout's `staging.human.standingHeightPx` over `heightPx`.
- *pixel ease*: the figure crop's changed pixels at each drawing of those moves also go small, large, small.

Control: a zigzag path with the right off-chord distance is refused on (a) only, a path that doubles back on (b), a hairpin on (c) only, and a smooth one-sided bow passes; a joints dump built by pure linear lerp (straight chord, even spacing) is refused on arcs and spacing; the same move with an arc offset and eased favours is accepted on all five checks; a reversal into an undeclared anticipation or out of an undeclared overshoot is refused on (b) and (c), the same declared passes, and a 3 px step back at 880 px is under the bar; a secondary snapped to the body's frame is refused on overlap; a declared moving hold that does not move is refused.

`probe-inbetweens.py --all v3/poses --frames-root out --joints-root out` runs every pose sheet: it expects `<frames-root>/<shot>-figure-seq/` and `<joints-root>/<shot>-joints.json`, prints one line per shot, prints `SKIP <shot>` for a shot whose frames or joints are missing, and fails (exit 1, "no shot had frames to measure") when nothing ran.

## Render cache (row 6.12, 6.13, D87)

**`npm run render -- <shot> [--force] [--layers figure,props,world,light] [--confirm 8] [--confirm-frames 0,150,300] [--confirm-cap 40] [--browsers 4] [--concurrency 1] [--no-video]`** (`render-cached.mjs`) renders a shot from cached layer drawings and writes `out/<shot>-seq/element-NNN.png` (composed frames), `out/<shot>-figure-seq/` (the figure layer alone, what the probes read), `out/<shot>.mp4`, `out/<shot>/render-manifest.json` and `out/<shot>/render-report.json` (wall times, drawings per layer, browsers; not part of the record). Exit 0 rendered with every confirm frame inside the determinism tolerance; 1 a confirm frame beyond it, naming the frame and the layer owning the largest difference; 2 input error. Only `s01-arrival-overwhelm` is wired (`SHOTS` in `render-manifest.mjs`: its pass module `src/scenes/shotS01Passes.ts` and what each layer reads). The drawings are drawn by `--browsers` Chrome instances (default 4, one tab each): the tabs of one Chrome share one GPU process and did not add up (1, 4, 8 and 12 tabs of one browser drew a `back` pass in 0.35, 0.30, 0.35 and 0.36 s per drawing; 4 browsers in 0.22 s).

**Layers and drawings.** The picture is a stack of passes (`shotS01Passes.ts`, pure, loaded in node by the manifest): `back` (the field, the flood and the motes over it, the Codex and the pieces behind the figure), `figure` (the parts rig), `front` (gadget, bubble, box, Clawd, front pieces, stalk, pop), `light-over` (the lamp's core, screen-blended), `grain` (three noise variants, screen-blended, opacity a frame parameter) and `title`. The manifest groups them into five layers: **figure**, **props** (back and front), **world** (the title lockup and the beat's contracts), **light** (core and grain) and **camera** (the pose of every frame; it has no drawings of its own). A drawing's id is `<pass>-<12 hex of the sha256 of its projection>`: two frames whose projection is the same JSON are one drawing. s01 measured: **730 drawings for 420 frames** (figure 161, props 420 = back 209 and front 211, light 148 = 145 cores and 3 grain, world 1); 61 distinct camera poses (the rest pose, the 60-frame widen, the held end pose). Taking the camera out of every projection would leave 617 (figure 126, back 180, front 187, cores 120, grain 3, title 1): the props and the lamp change on ones through the rise and the flood whatever the camera does.

**Cache.** `out/cache/<shot>/<layer>/<cacheKey16>/<drawing>.png` (cropped to its alpha box) and `index.json` (box, sha256). A layer's `cacheKey` is the hash of the inputs a DRAWING reads at draw time: its `inputs` less its `projectionOnly` ones. A file that only shapes the projection is already in the drawing's id through what it produced, so editing it makes the layer's `inputsHash` stale (the gate names it) and redraws only the drawings whose projection changed. The figure's `projectionOnly` are the pose sheet, the key sheet and the key plates (`plates.json`, `K<n>.png`): the film draws the parts, the mesh and the skeleton, and no composition loads the key plates; a key moved 3 px redraws the 13 of 161 figure drawings that show it. A layer is **HIT** when every drawing it needs is cached under its current cache key, **MISS** when any had to be drawn; `counts` says how many were reused and rendered. `--force` redraws the selected layers; `--layers` limits the redraw and refuses to compose over a layer with missing drawings. A frame is written again only when its recorded compose key or file hash differs, so a run with nothing changed writes no file and leaves the manifest byte-identical (the manifest holds no times). The drawings are drawn in frame order, a run of one pass per browser, and composed in 12 workers over contiguous runs of frames (PNG level 1 for frames, 3 for drawings).

**Manifest.** `render-manifest.mjs <shot>` computes the inputs half (no render): per layer `inputs` (path to sha256; `path#a.b` hashes one subtree of a JSON file in a canonical form `probe-render-manifest.py` reproduces), the renderer's source closure under `code:<codeVersion>` (esbuild's import graph from `ShotS01.tsx` and `shotS01Passes.ts`, listed in `codeFiles`; one codeVersion, so a source edit misses every layer), `inputsHash`, `projectionOnly` and `cacheKey` (above), `drawings` (`id`, `pass`, `frames`, `outputHash`), `outputHash`, `status`; per frame `layers` (drawing ids), `camera {x, y, zoom, rot}`, `magnification` (`magnifiedChangeOf`: the largest on-screen scale of a prop whose drawing changes on that frame, 0 when none does), `params` (field, grain and title opacity), `outputHash`, `figureHash`, compose keys; and `confirm` (`tolerance`, `plan`, `frames`). It refuses (exit 2) when the renderer imports a data file no layer declares.

**Camera.** The camera is baked into every drawing under it (it is part of the projection, so part of the id) and the compositor only places. The design's alternative, drawings at the identity camera moved by `cameraTransform` (`translate/rotate/scale` about the stage centre), was measured twice and does not hold. (1) Reach: the widen reveals content outside the 1280x720 frame (the camera's views over the shot cover x 0-1280, y -197 to 720, so an identity canvas would be 1280x917). (2) Raster: the figure pass drawn at the identity camera and resampled to the frame's pose (PIL affine, bilinear, premultiplied, the pixel-centre alignment) against the same pass baked at that pose: frame 160 (zoom 0.963) 4 450 pixels beyond 2 levels (largest 14), frame 180 (0.775) 4 619, frame 205 (0.606) 4 358 (largest 124), frame 300 (0.600) 3 492 (largest 141; 2 694 at the best of 49 sub-pixel shifts, largest 43); bicubic is worse (4 478-11 555). The allowance is 92 and this is the figure alone. The browser draws the figure's WebGL bitmap through the compositor's own filter at the pose's scale and vector content at the pose's scale, neither of which a resample reproduces. So the camera stays baked at every zoom but 1, caching per distinct pose: a hold on the end pose is one drawing per distinct state, and the 59 frames of the move have a pose of their own.

**Confirm.** `render` draws the frames of its plan whole through the browser (`out/<shot>-confirm/`) and compares each with the composed frame: MAD, pixels beyond 2 levels, the allowance (0.01 % of the frame, 92 at 1280x720) and, on a failure, the layer whose drawings cover the most differing pixels. The plan is the defaults (the first frame, the last and the key frames, thinned to `--confirm`, 8) plus every frame where a drawing of any layer changes from the frame before and a prop is magnified above 1.5 on screen (`magnifiedChangeOf`), thinned evenly to `--confirm-cap` (40) in all; `--confirm-frames` adds named frames to it. On s01 57 frames are candidates and 32 are taken beside the 8 defaults. The record is `confirm` in the manifest: `plan` (the rule, the cap, the threshold, the candidate count, whether it was thinned, and `chosen`: each frame with why) and `frames` (the comparisons), and `probe-render-manifest.py` recomputes the candidates from the frame rows. It is a sample: the composed frame is the same drawings composited in float and rounded once, the browser's rounds after every draw; `sweep-compose.py` (below) compares all 420.

**Measured limits.** (1) Passes drawn apart are not the passes the whole frame draws, because the browser decides how to rasterise the layers inside one camera transform from everything they hold: at zoom 0.6 the pieces come out soft in the whole frame and sharp when drawn without the motes beside them, so the light under and the props behind the figure are ONE drawing (`back`), and each pass inside the transform carries an empty WebGL canvas where the figure's is (`FigureCanvasShim`: a pass without it sits half a pixel off Clawd's outline). ## Pose pass tools

**joints.mjs `<shot-id> [--out out/<shot>-joints.json]`** (`npm run joints -- <shot-id>`) loads the shot's plan through `load-ts.mjs` (s01: `src/scenes/shotS01Plan.ts`, which runs `poseAt` per frame) and writes `{shot, fps, frames: [first, last), parents, rows: [{frame, phase, from, to, favour, camera, joints}]}` for every frame, quantised on twos exactly as the renderer draws. **arcs-image.py `<before-joints> <after-joints> --poses v3/poses/<shot>.json --out out/<shot>-arcs.png [--moves a>b,...] [--json out]`** draws, per move, the paths of the lead wrist, the head and the root before (pale, dashed) and after (solid) a pose-chart change, with each drawing a dot, and prints per move the lead joint's drawings, largest deviation, sign changes (an arc has none) and whether progress along the chord is monotone, read with `arc_faults` from `probe_common.py`. Joints files come from `joints.mjs` (keep the before file with `--out`).

**solve-poses.mjs `<shot-id>`** (`npm run solve-poses -- <shot-id>`) runs `solvePose` for every key of `v3/poses/<shot>.json` over the rest skeleton `check-pose.mjs` uses (`assets/human/skeleton.json`, restHeightPx 922, scaled to the sheet's `heightPx`; s01's is 922, the home family's rest figure, so a solved joint is a position in the home mesh) and writes the joints back into each key as `solved: {joint: [x, y]}` (the key sheet's joint names, 2 decimals) with `solvedAt` (ISO date); it prints per key the class and bow the solved spine reads back. Run it again after any change to a key's line of action, weight, lead or the sheet's `heightPx`, then `npm run plates`: `probe-poses.py` refuses a solver key whose joints are not its `solved` ones. `solvePose` keeps every bone at its rest length (`check-pose.mjs` refuses a solved key with any bone more than 1 % off, with a left arm drawn 12 % long as its control): the trunk bones are walked along the declared curve (the neck and head bones are 18-19 px, and a bow of 0.12 placed on a fixed chord fraction stretched them 3x and sheared the mesh the joints pin) and the loop is closed on the spine fit; an S the short neck and head bones cannot draw is helped by tilting the shoulder line against the trunk (`SHOULDER_TILT_MAX`, 35 degrees, smallest tilt that reads closest) and may read under its declared bow, down to the 0.06 floor (K4 awe 0.075, K7 joy-b 0.071 against 0.10 and 0.12). Arms and legs are two-bone chains placed by IK toward the target the declaration implies: legs from the weight foot under the root and the lead foot stepped out and up; the wrists from the silhouette kind (`SILHOUETTE_ARMS`): `star` both wrists above the shoulders and 0.12 H or more from the spine (the lead arm higher and further out), `open` both 0.14 H or more off the spine, `closed` and `fold` both hands near the torso (a fold crosses them), `line` along the spine's curve past the head; a target out of reach shortens the reach or bends the elbow or knee, never a bone (`check-pose.mjs` checks the wrists per kind with a control).

**check-pose.mjs `[v3/poses/<shot>.json]`** (`npm run check:pose`) proves `pose.ts`: `solvePose` of every key's spec reads back through `spineCurve` as the declared class with a bow within 0.02 (an S may read under its declared bow, down to the 0.06 floor, where the short neck and head bones cannot draw more); `parsePoseSheet` refuses an unknown class, a bow of 0.5, a favour of 0.5, a breakdown naming an unknown key, a lag of 4, a stretch of 1.5 or -0.1, a twinned key with no `why`, and the timing shape (a move of ten drawings, a passing drawing at 0.10, an anticipation at -0.20, an overshoot at 1.02, a settle at 0.8, two anticipations, a settle before a passing drawing, a breakdown inside the hold); `poseChartFrom` through `poseAt` shows a breakdown's own joints, lands a secondary `lagDrawings` x 2 frames after the body, drifts a moving hold and keeps the drift until the first drawing of the move that leaves the key, and the same chart with its lags and drifts removed does none of it. Control first: an `S` declared on a straight spine does not read back.

**plates-from-poses.mjs `<shot-id>`** (`npm run plates -- <shot-id>`, D85) builds the key plates in the project from the solved joints. Per key of `v3/poses/<shot>.json` the key's `solved` joints become its registered joints in `v3/keys/<shot>.json` (`source: "solver"`), and the plate families that may draw it are tried in order (`assets/<actor>/families/<plateFamily>`, then `home`): a family with parts (`npm run parts`, below) is a parts rig, a family without is one ARAP mesh. Each mesh is posed by ARAP (the solver the renderer runs) with the solved joints as pins, and the first family that holds the pose (`render-plates.py`: at most 1 % of the mesh turned inside out, 6 % strained past singular values 0.5-2.0, 5 % drawn over another part beyond what the rest mesh covers twice; provisional limits set on the first eight renders; for a parts rig each part's own mesh is measured and every part must hold) is drawn to `assets/<actor>/keys/<shot>/K<n>.png` at the model sheet's measured scale (`plate_tools.model_figure`: hair top to baseline, 437 px, 0.4745 plate px per mask px; `model.json`'s `figureHeightPx` is that 437 since 2026-10-15, the 470-471 it read before included the numeral under the baseline) on its baseline, role colours snapped once at full resolution so thin contours keep crisp edges, alpha softened at sigma 1.1 (D71), the contour the family plate carries kept (D76), `K<n>-crop.png` over a pure black field, mirrored to `public/`. A key no family holds is reported `NEEDS FAMILY` with its family and silhouette kind, gets no plate (`status: "needs-family"` in the key sheet), and `probe-poses.py --joints keys` refuses it by name; it is never drawn anyway. Control first: the home mesh at rest holds, shifted rigidly holds, and one arm turned 140 degrees across the torso does not; for the parts rig, the parts at rest and shifted rigidly hold, the poncho's right half turned 150 degrees does not, and the hinge control (below) names the joints of a composite with its overlap removed. Order after any change: `parts` (only when the family plate or the cut changed), `solve-poses`, `plates`, `author-breakdowns` (the hash below), then the renders and `probe-all`. Then `measure-keys.py` runs.

**cut-parts.mjs `[<actor> [<family>]]`** (`npm run parts`, row 6.9) cuts a plate family into the parts of the parts rig and writes `assets/<actor>/families/<family>/parts/{<part>.png, <part>.ramp.png, owners.png, parts.json}` (`scripts/lib/parts.mjs` `loadParts` refuses parts cut from a plate that has since changed). The parts are hair, head, torso (neck and collar), poncho, and left and right upper arm (the cape's sleeve), forearm, hand, upper leg, lower leg and foot. `cut_parts.py` gives every pixel of the plate to a part: the plate's own pale contour lines are taken out and the faces that remain are grouped (head and hair above the collar, arm, leg, cape); inside a group the skeleton cuts, never a hand-placed outline: the head is the disc the face's green fills, a hand lies past the wrist plane of its forearm, a foot past the ankle plane of its shin, a leg splits at the knee plane, a forearm starts at the elbow plane, a sleeve is the cape nearer its shoulder-to-elbow bone than the cape's axis and below the shoulder plane. Every border therefore passes through its joint. Where two parts meet each reaches into the other (the part in front of a drawn contour, the hem of the sleeve over the forearm, the cape over the legs, the chin over hair and neck, reaches into nothing and the part behind reaches under it; a forearm reaches under its sleeve with its own skin carried on, not with the sleeve's lining), a slab of 10 mask px (about one contour width, 7.6 mask px at the model sheet's scale) and at a joint a cap, the disc of the limb's half width about the joint (at most 30 px), so a limb bent about the joint never opens a notch on its outer side. Inside the reach both parts hold the same plate pixels; at pose time the part drawn in front fades out across its reach (`<part>.ramp.png`: 0 in its own cell, 1 at the end of the reach, applied where the pixel belongs to a part it is in front of) over the part behind, which is opaque there, so a joint is a soft overlap and never a cut. The tops of the upper legs, hidden under the cape in the drawing, are continued upward by the cross-section the cape leaves visible. Each part is its own ARAP mesh (`maskToMesh`, grid 14 px); `parts.json` carries per part its bone, its mode (`limb`: pinned at its own joints and free to stretch along the bone; `rigid`: moves by its bone's rotation about a pivot joint, pins are that joint and three anchors: head, hair, hands, feet), its pins (a pin on a joint that lies outside the part, the cape tip drawn short of the poncho-point joint, pins the nearest interior point and carries it by the bone's rotation), its default `z`, its neighbours and the cap of each joint.

**Draw order** (`src/library/motion/partsRig.ts`, the code both `plates-from-poses.mjs` and the film's `MeshFigure` run for the pins and the order): `defaultOrder(parts, solved joints, lead, weight foot)` gives the parts front to back. At rest the order is hair, legs (the foot behind the lower leg behind the upper leg), the forearm and hand behind the poncho, the poncho, the sleeve, the torso, the head; the lead arm (and an arm whose wrist crosses the spine, which sits under the lead arm) is drawn in front of the torso and the head, the lead leg (or, with no lead leg, a leg that crosses the other with the weight on the other foot, or an ankle that crosses the spine) in front of the other leg, and the poncho stays behind the torso and the hair behind the head. A pose-sheet key may carry `order`, a list of parts front first: the parts it lists exchange the places the rule gave them in the order listed, the others keep theirs (`parsePoseSheet` refuses a name that is not a part, a duplicate or a single name). The key sheet records the order used and the limbs the rule put in front (`render.order`, `render.depths`). The film draws the order of the key a move runs toward, frame by frame from that frame's joints.

**Hinge measure** (`parts_tools.joint_fill`, per key at the shoulders, elbows and knees; the anti-reference of the rubric is a hinge-jointed cutout): `fill` is the share of the disc one contour width wide (the model sheet's 3.6 plate px) about the joint that the composite draws, which must be all of it; the overlap is `fade`, the width in contour widths of the soft band the part in front makes over the part behind about the joint (the area of the pixels where its alpha lies between 0.1 and 0.9 over the part behind, within the joint's reach, over the limb's width), or `depth`, how far the part behind reaches under the front one (the area where both are opaque; where the front part ends in a line the artist drew, the sleeve's hem over the forearm, it has no fade and the forearm's own extruded cap is the depth), and the larger must be at least half a contour width. A cut ends the part in a line one or two pixels wide: 0.2-0.3. The real parts measure about 1.5 at rest. Control first (`render-plates.py`): the same parts with their overlap removed are named at all six joints at rest (a straight seam: overlap 0.0), and with the elbows and knees bent 90 degrees at those four (an open disc: fill 0.71-0.87), while the real parts, rest and bent, fill every disc. A key whose joints fail is `REJECTED: JOINTS` in the keys table. Known limit: where a limb swings far off a neighbour the reach that stays with it (a copy of the neighbour's pixels, at most 10 px wide along the border and a cap at the joint) fades out in the air as a soft wedge; it is the price of never showing a crack.

**measure-keys.py `<shot-id>`** writes `measured` per key into `v3/keys/<shot>.json` and `out/<shot>-keys-table.txt`: C20 head count and limb scales read off the posed mesh (the local scale of the triangles under the head and along the middle 80 % of each limb's bones, within 5 %), C21 the filled silhouette (`scripts/measure-silhouette.py` on `out/<shot>-keys-silhouettes/`, one component, and the wrists the silhouette kind needs clear of the spine), C22 the contour by the key sheets' own measure against the model sheet's three figures by the same measure (within 20 %; control: the same plate with its pale lines grown by two pixels falls outside), C31 the per-key class, bow, sign and twinning by `probe-poses.py`'s own checks; for a parts rig the limb scales are the stretch along the two bones of each limb (the later of two definitions of `part_scales` in `plate_tools.py` had silently replaced this one with the area scale; the duplicate is removed), a second table block per key (worst tear metric over the parts and which part, the hinge measure, the limbs in front and the draw order) and the joint check above. Exit 1 when a key fails or needs a family. **Plate versus film** (`film_compare.py`, `npm run film-keys`): `plates-from-poses.mjs` renders the film rig's picture of every key first (`src/scenes/KeyFilmS01.tsx`: the key's joints through `FlatFigure`, the component the film draws the human with, in the order the film draws that key in, no background, camera at identity, scale 0.9; frame k is key k + 1 and the last frame is the control), and `measure-keys.py` maps it into the plate's pixel space with the registration numbers and the placement `KEY_FILM` exports, snaps its colours to the palette and compares: `mad`, the mean absolute difference of the role colours over the union of the two silhouettes (0-255), and the distance between the centroids of the head, each hand and each foot (plate px). A key is `REJECTED: FILM` when a centroid is more than one contour width apart or `mad` exceeds 10.0: the eight keys that agree measure 7.3-9.6 and under 1 plate px, the control (K1 with its right hand drawn behind its left upper leg) 12.3 and 6.2 px, so it is named. If the two disagree, the pose or the order is not shared: fix `partsRig.ts`, never the bar. The first run of this measure found the film canvas cut an arm thrown wider than the rest figure (K1, K6): `MeshFigure` now covers 300 canvas px either side (`PAD_SIDE`). It compares the key's own joints, not the film's frames (a secondary that lags the key and a hold's drift are the chart's, measured by `probe-inbetweens.py`).

**Plate families** are `assets/<actor>/families/<family>/{plate.png, mesh.json, joints.json}` (and, once `npm run parts` has run, `parts/`) (`scripts/lib/families.mjs` loads and verifies them): a mesh built from one drawn plate with its own skeleton registration, `registration` one of `skeleton` (the home family: the D73 skeleton on the approved model-sheet plate), `toolchain` (tech-rig-01's output, numeric gate passed; not installed here) or `fit`. **family.mjs `<actor> <family> --plate p.png --shot <shot> --key <key> --silhouette <kind>`** cuts a generator's plate into a family and registers it by `fit-family.py`: the solved joints of the key the plate was asked to draw fitted to the plate's mask by scale and translation only, believed only when every bone group lies in the mask (0.90) and the skeleton explains the silhouette (0.80); a plate the skeleton does not agree with is refused with the numbers and nothing is written (control: the home plate with its own skeleton passes, the same skeleton held 90 px off fails). `out/s01-03-families.txt` holds the run on the eight run-2 generator plates.

*Stale breakdowns*: `author-breakdowns.mjs` writes `keysHash` on every breakdown it authors, the sha256 of the joints of the two keys the move runs between (`probe_common.keys_hash`: joints in name order as `name=x,y` at two decimals, the keys joined by `|`). `probe-poses.py` refuses, on the `breakdowns` check and per move, an authored breakdown whose keys have moved since or that carries no hash; its control plants the same sheet on keys that moved, on no hash, and on the keys it was built on. It also refuses a key sheet entry with `status: "needs-family"` (on `keys`, naming the family and the silhouette) and a `source: "solver"` key whose joints are more than 0.05 px from the pose sheet's `solved`.
