###   BREAKING CHANGES

* **cli:** config changes are versions cpm can restore ([#347](https://github.com/minipuft/claude-prompts-mcp/issues/347))
* **mcp-tools:** every tool refuses an argument key it does not declare ([#344](https://github.com/minipuft/claude-prompts-mcp/issues/344))
* **mcp-tools:** a resource_manager key that nothing reads is refused ([#342](https://github.com/minipuft/claude-prompts-mcp/issues/342))
* **mcp-tools:** a parameter the resource type ignores is refused ([#337](https://github.com/minipuft/claude-prompts-mcp/issues/337))

* **config:** a workspace config can be config.jsonc, every setting a commented example ([#338](https://github.com/minipuft/claude-prompts-mcp/issues/338))
* **config:** every config key resolves the same from a 4.x file, a 5.0 file, or over MCP ([#325](https://github.com/minipuft/claude-prompts-mcp/issues/325))
* **frameworks:** framework tool text adds to each tool's description ([#323](https://github.com/minipuft/claude-prompts-mcp/issues/323))
* **config:** one generated authority describes the 5.0 config.json ([#322](https://github.com/minipuft/claude-prompts-mcp/issues/322))
* **config:** configuration is read-only over MCP ([#312](https://github.com/minipuft/claude-prompts-mcp/issues/312))
* **runtime:** a workspace, resources directory or workspace config.json the server cannot use now stops it from starting instead of being silently created, replaced or ignored.
* **runtime:** a config path set with `MCP_CONFIG_PATH` or `--config` that cannot be used now stops the server instead of starting it on defaults.
* **mcp-tools:** every mutation intent gets a verb the tool can refuse ([#262](https://github.com/minipuft/claude-prompts-mcp/issues/262))
* **server:** three gate/resource YAML contracts change, each with the migration in the error message.
* **server:** the HTTP transport now binds 127.0.0.1 by default and the four /api/v1/tools/ routes require MCP_TOOLS_WRITE_TOKEN. Deployments reaching the server across a network must set MCP_HTTP_HOST, and any client calling the tool routes must present the new token.
* **gates:** a gate criterion that cannot be enforced is refused at load. `shell_verify` without `shell_command` and `script_tool` without `script_tool_id` fail gate loading, naming the missing field. Both previously auto-passed at review time, so a gate declaring a check it could not perform reported as verified -- the strongest available evidence for the one outcome that carries none. Gate YAML is contract surface, so this is priced as breaking even though nothing in this repository or the three downstream consumers relies on the old permissiveness.
* **hooks:** delete the blocking subagent-gate-enforce hook (S3)
* **execution:** the rendered ==> handoff text  a client-observable prompt surface  changes shape entirely (brief-at-resume replaces CTA-at-preview).
* **mcp-tools:** `system_control(action:"session", operation:"cancel")` is removed; call `prompt_engine(chain_id:"...", cancel:true)` instead. The removed operation now refuses with a message naming the replacement rather than reporting an unknown operation. `resource_manager` additionally accepts `source_workspace`. Both alter the reachable-shape union of the MCP tool surface, which this repository's Public API Contract prices as breaking.
